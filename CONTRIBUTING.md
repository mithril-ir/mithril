# Contributing to Mithril

Thanks for your interest in Mithril. Please read this short document before opening an issue or pull request.

## Where the project stands

Mithril's compiler backends are **not implemented** beyond two deliberately narrow slices of the same verified obligation family — the structurally gated NoSelfPrivilegeEscalation verifier slice described below (two exact case rules: the `Membership.changeRole` change-other rule and the bounded self-update rule, over non-empty case collections), and the first confined Wasp target slice, `mithril wasp generate|check`, which lowers exactly the verified singleton `Membership.changeRole` (rule-1) obligation and refuses every other verified plan at its Profile-v0 gate into a closed, checked Wasp 0.25.0/PostgreSQL application profile (the Wasp Confinement Profile v0) — and no general target-code backend exists; the frontend through the typed normalized Core and the deterministic contract renderer are implemented. On the Haskell side the repository contains the `mithril-ir` Cabal package (GHC 9.12.4, cabal-install 3.18.1.0, GHC2021) whose `mithril` CLI prints help and version output and implements the four deterministic frontend boundaries: `mithril validate FILE`, JSON parsing, structural Core v0 validation against the canonical `core/schema.json` compiled into the tool at build time — no runtime file or environment lookup selects the grammar — (JSON parsing via `aeson`; validation via the exactly pinned, provisional `jsonschema 0.3.0.1` behind an explicit schema-profile gate), complete Core v0 name resolution (declaration-name uniqueness per namespace, resolution of every name reference, and the resolver's one recorded designation of the distinguished `User` entity; deterministic maps and sets via the direct `containers` dependency), complete Core v0 static typing of the resolved document (term, policy, effect, and result types; operand, relation-endpoint, and payload compatibility; enum-order permutation validity; `CreateEntity` initializer completeness; guarantee well-typedness — with no new dependency), and deterministic Core v0 normalization of the well-typed document (statically typed terms via the typechecker's own judgment, materialized enum ranks, explicit endpoint bindings, declaration-ordered `CreateEntity` initializers, explicit guarantee structure, and the distinguished `User` identity — selected once by the resolver, validated and carried by the typechecker — carried as an independent anchor for the backends' subject and `Actor` checks — again with no new dependency), plus the first consumer of the typed normalized Core: `mithril contract FILE`, the same complete pipeline followed by deterministic rendering of the normalized document as a line-oriented, human-readable security contract whose exact bytes are frozen by golden and literal tests (no new dependency either), plus the first connected verifier slice: `mithril verify FILE`, the same complete pipeline followed by a pure deterministic support gate and — for exactly one supported NoSelfPrivilegeEscalation obligation family, every selected case matching one of two exact structural rules (change-other, bounded self-update) — deterministic generation of an Agda obligation module with one proof group and checked manifest per case, checked by exactly Agda 2.8.0 in safe mode against kernel modules embedded at compile time (the checker boundary added only the GHC boot libraries `directory`, `filepath`, and `process`; a supported document is VERIFIED with exit 0, everything else — the canonical Acme example included — is UNSUPPORTED with exit 3, and checker problems are tool failures with exit 2, never verdicts), together with unit tests, process-level CLI regression tests over the built executable, downstream API-boundary compile-fail probes, and pinned Haskell CI, plus the first confined target slice: `mithril wasp generate CORE_FILE WASP_ROOT` and `mithril wasp check CORE_FILE WASP_ROOT`, the same complete pipeline and the verify gate (VERIFIED required) followed by deterministic lowering of the one shared NoSelfPrivilegeEscalation support plan — the exact classification the verifier consumed, stated once in a package-private facility both backends share — into a closed Wasp 0.25.0 application on PostgreSQL whose specification, Prisma schema, one authenticated Action declaration and generated TypeScript implementation (Wasp authentication, `context.user.id` as the only identity, argument validation, the authorization reads and the `SetRelation` write in one Prisma interactive transaction at `Serializable` isolation with a bounded deterministic `P2034` retry, no raw SQL), dependency, TypeScript, and Vite configuration, minimal static client shell, and generation manifest are all managed inputs; every identifier, filename, and route of the bundle is a fixed role-derived target name rather than an authored name; `generate` installs the bundle as a complete root (an absent or empty root is initialized, an owned root is replaced by whole-directory renames with rollback, an unmarked nonempty root or an unmanaged path is refused without mutation) after validating the root path lexically and its ancestors with no-follow metadata, and finishes with the confinement check, while `check` performs no writes, walks the complete source root without following symbolic links, rejects hard links, compares every managed file byte-for-byte with the regenerated bundle, and rejects missing, altered, and unexpected inputs (exit 4) with deterministic sorted diagnostics — the authority is the regenerated closed path inventory plus exact bytes, never the denylist scan that merely labels bypasses (the committed golden fixture `test/fixtures/wasp-acme` is the reviewed generated output, pinned byte-for-byte; the pure renderer attests supported-shape lowering only, and the VERIFIED provenance is stated by the commands after the verifier reported it; a separate pinned CI job runs the real Wasp 0.25.0 / PostgreSQL vertical battery, installing, compiling, and building the freshly generated root itself and exercising it through Wasp's generated HTTP and authentication path). A successfully resolved document is carried as an explicit internal decoded and name-resolved Core representation — resolved references use internal identifiers and retain JSON source paths, and generic JSON ends at the internal decode boundary — the typechecker consumes exactly that representation, the normalizer turns the well-typed document into a distinct explicit typed normalized representation, and the contract renderer consumes exactly that normalized representation, repeating no earlier stage; but structural validation still establishes JSON shape only, name resolution establishes names only, static typing establishes the Core v0 typing judgments only, normalization establishes deterministic structural canonicalization of one authored document only — no boolean simplification, constant folding, operand reordering, policy evaluation, or canonical equality between differently authored documents — contract rendering establishes a deterministic restatement for human review only (its rendered guarantees stay explicitly labelled unverified proof obligations, and it is not a semantic diff), and the internal representations prove no property. No complete Mithril verifier, policy evaluator, or semantic diff exists, and the only implemented generators are the verifier slice's narrow single-obligation Agda proof-artifact generator (whose generated module carries an Agda-checked in-module theorem manifest per case) and the Wasp emitter of exactly the singleton rule-1 form of that same obligation (whose bundle carries a deterministic `mithril.manifest.json`) — there is no general JSON-to-Agda generator, no general Wasp backend, no whole-product generator, and no production code generator beyond the one closed demonstrator, no policy is evaluated, no semantic-preservation theorem between Core and the generated TypeScript exists, and beyond the one supported obligation of a supported document no guarantee is established; the Haskell generator and emitter, the embedded Agda kernel, the Agda 2.8.0 toolchain, the support rule, and — for the Wasp slice — Wasp, Node, Prisma, PostgreSQL, the templates, and the lowering remain trusted components, while malicious concurrent same-user mutation after the final check, malicious checker or CI changes, dependency compromise, external processes holding database credentials, and tampering after the Wasp build are outside the confinement claim; see [`docs/compiler-architecture.md`](docs/compiler-architecture.md).

The canonical Haskell checks, run from the repository root:

```
cabal check
cabal build all --enable-tests
cabal test all --test-show-details=direct
sh test/api-probes/run-api-probes.sh
cabal run mithril -- --help
cabal run mithril -- --version
cabal run mithril -- validate examples/acme/acme.mir.json
cabal run mithril -- contract examples/acme/acme.mir.json
cabal run mithril -- verify test/fixtures/acme-nspe.mir.json
cabal run mithril -- verify test/fixtures/acme-nspe-self-update.mir.json
cabal run mithril -- verify test/fixtures/acme-nspe-dangerous.mir.json
cabal run mithril -- verify examples/acme/acme.mir.json
cabal run mithril -- wasp check test/fixtures/acme-nspe.mir.json test/fixtures/wasp-acme
sh test/wasp-integration/test-harness.sh
sh test/api-probes/test-run-api-probes.sh
```

CI runs all of them on every push and pull request; none of them needs Wasp, Node, or PostgreSQL (the penultimate one is the self-test of the integration harness library — the physical working directory under a symlinked `TMPDIR`, database ownership, identity-bound process termination, and cleanup — driven with stubbed database and kill commands and a fake proc tree, plus the built `mithril` and Agda 2.8.0 for its one generation smoke test; the last one runs the probe driver twice concurrently from a clean copy of the sources and proves disjoint build roots and no default `dist-newstyle`). The real Wasp 0.25.0 / PostgreSQL vertical battery is a separate pinned CI job (`.github/workflows/wasp.yml`, one job per database branch) running `sh test/wasp-integration/run-wasp-integration.sh`, which needs the Wasp 0.25.0 CLI, Node.js 24, and PostgreSQL 16 (either the server binaries for a private `initdb` cluster or `MITHRIL_PG_ADMIN_URL` naming an administrative connection, where the run owns and drops only the database it created) besides the pinned Haskell toolchain and Agda 2.8.0; it generates into a private working directory and installs, compiles, and builds that freshly generated root and every committed rename variant there, so `node_modules`, `.wasp`, `package-lock.json`, and migrations never enter the repository. The test suite and the first two verify commands invoke the real Agda 2.8.0 executable, which must be on the search path (CI installs it in the Haskell workflow as well as the spike workflow); the third and fourth verify commands deliberately exit 3 — the dangerous self-promotion mutation and the canonical Acme document are UNSUPPORTED, never verified and never reported as violations. Run them locally before submitting a change that touches the Haskell tool, `core/schema.json`, `examples/acme/acme.mir.json`, or the embedded kernel modules under `agda/`; the validate command must keep reporting the Acme example as valid Mithril Core v0 through normalization, the contract command must keep rendering its frozen security contract, and the verify commands must keep their exit statuses, and the wasp check command must keep reporting the committed generated fixture `test/fixtures/wasp-acme` CONFINED (the exact contract, generated-Agda — `nspe.generated.agda` and `nspe-self-update.generated.agda` — and generated-Wasp bytes are pinned by the test suite's golden files under `test/fixtures/`; the generated goldens are regenerated only through the tool's generator and reviewed, never hand-edited). The probe script builds the expected-to-fail downstream package under `test/api-probes/` with a dedicated project file (`cabal.project.probes`) and verifies that every attack on the stage abstraction — importing the hidden document, representation, typechecker, normalized-representation, normalizer, contract-renderer, verifier/planner, shared-support-plan, Wasp-emitter, Wasp-confinement, Wasp-filesystem, embedded-Agda-kernel, or Agda-checker modules, calling the `CoreDocument` constructor (including to forge a `Typed` or `Normalized` document), coercing between stages (including from `Resolved` to `Typed` and from `Typed` to `Normalized`) or from a raw JSON value into a stage, coercing a resolved document back to a raw JSON value, passing a merely `Typed` document to the public contract renderer or the public verifier, or passing a merely `Parsed`, `StructurallyValid`, `Resolved`, or `Typed` document to the public Wasp emitter — still fails to compile for its intended reason, and that every hidden-module attack compiles and links warning-free under the repository warning set and an unweakened `-Werror` when its module is deliberately made visible (so each fails for the hidden-module diagnostic alone); because the internal representation, typechecker, normalizer, contract-renderer, verifier, support-plan, emitter, confinement, filesystem, kernel, and checker modules cannot even be imported, downstream code can neither construct resolved or normalized nodes, typed or normalized documents, mint or cross-coerce internal identifiers, run the support gate, the Agda generator, or the Wasp lowering outside the staged pipeline, forge a plan or a bundle, install a bundle or inject faults into the installation seam, read or substitute the embedded Agda kernel, nor invoke the production checker runner directly. The compiling control exercises the legitimate pipeline through normalization and the public contract, Wasp-emitter, and verification APIs (without executing Agda at compile time). The same script then builds the flag-gated in-package probes of `mithril-ir` itself: after their control proves the real internal identifier definitions are in scope, the attack executables attempt cross-namespace `coerce` between global identifier types and must fail with GHC's representation-mismatch error — the identifier namespaces are distinct data types, non-coercible even for code inside the package. It needs a POSIX shell in addition to the pinned toolchain (on platforms without one, CI remains the authoritative runner).

The representation modules — resolved and normalized alike, with the shared static type language — live in a package-private named sublibrary of `mithril-ir` (`visibility: private`). That is an internal testability and encapsulation mechanism, not a packaging or distribution decision: no other package can depend on it or import its modules, while the package's own test suite uses it to white-box-inspect the real resolved and normalized models — identifiers, owners, retained JSON source paths, stamped static types, materialized ranks, and canonical initializer order — produced by the production pipeline, alongside the black-box pipeline checks.

If a `core/schema.json` change affects declaration namespaces, reference-bearing fields, Core constructors, enum uniqueness/order or `User` assumptions, or structural invariants used by resolution, typing, or normalization, follow the [mandatory schema-and-resolver audit](docs/compiler-architecture.md#schema-and-resolver-evolution): audit the internal schema decoder and the decoded/resolved representation's construct coverage as well as `Mithril.Core.Resolution`, the static typechecker behind `Mithril.Core.Typing`, the normalizer with the normalized representation's construct coverage behind `Mithril.Core.Normalization`, and the contract renderer's rendering-branch coverage behind `Mithril.Core.Contract` (its consumption matrix and frozen golden contracts pin every current constructor family), identify every changed constructor and reference location, and add the relevant targeted regressions in the same change. Recompilation only detects changed schema bytes; passing structural validation and compilation does not establish decoder, representation, resolver, typechecker, normalizer, or renderer completeness — that completeness remains a manually reviewed obligation, not an automated proof.

Two operational caveats of the current validator — known gaps, not contracts: duplicate JSON object members are accepted under Aeson's member semantics rather than rejected (no particular occurrence is contractually the winner), and no independent input-size, nesting, memory, or execution-resource limits exist yet. Do not describe `mithril validate` as hardened validation for arbitrary untrusted, unbounded input. Neither caveat affects the narrower claim that the unchanged Acme example structurally validates, resolves, typechecks, and normalizes.

- **No lint or formatting command has been selected.** Do not invent one — any Haskell lint or format command you find elsewhere is not real. Such tools will be documented here if and when they are chosen.
- The experimental Agda semantic spike described below stays separate from the Haskell scaffold; its checks are real and remain required whenever files under `agda/` change.
- The most valuable contributions right now are design discussion, review of the scope and non-guarantees documented in the README, and prior-art references — not product code.

### The experimental Agda semantic spike

The repository does contain an experimental Agda mechanization of candidate kernel semantics under `agda/`. It is an exploratory spike, not a product prototype, and it does not select Agda as the implementation language.

It requires **exactly Agda 2.8.0** and uses Agda builtins only (no standard library and no other external library). Its only application-level result is one checked, hand-transcribed, fixed-schema proof slice (see [`agda/README.md`](agda/README.md)): the Acme example's `Membership.changeRole` action satisfies its selected NoSelfPrivilegeEscalation case, with checked negative evidence that an unsafe self-promotion variant violates the same proposition. Five spike modules (`Base`, `Core`, `Policy`, `Effect`, `Guarantee`) now also serve as the trusted kernel the host tool embeds at compile time for `mithril verify`; changing them changes the verifier's trusted computing base and must keep both spike checks and the Haskell test suite passing. Everything else remains unverified: there is no general JSON-to-Agda generation (the implemented verifier covers exactly one obligation family with two exact case rules), neither `examples/acme/acme.mir.json` nor the complete Acme model is verified, no other action or guarantee family (TenantIsolation, AuthenticatedMutation) is proved, and the slice is an experiment, not a product verifier.

Its two authoritative checks are real commands. Run both from the repository root, and run each from deleted `.agdai` interfaces so that neither check can succeed through interfaces produced by the other:

```
find . -type f -name '*.agdai' -delete
agda --safe -i agda agda/Mithril/Everything.agda

find . -type f -name '*.agdai' -delete
agda --safe --no-libraries --ignore-interfaces -i agda agda/Mithril/Everything.agda
```

[`agda/README.md`](agda/README.md) is the detailed source for the spike's boundary and these commands. Changes touching `agda/` must keep both checks passing.

## Discuss before building

Major architectural changes — the design of Mithril Core, the verification approach, the code-generation strategy — should be **discussed in an issue before any implementation work begins**. A pull request that lands a large unsolicited design is likely to be closed in favor of a discussion, however good the code is. Small fixes (typos, broken links, clarifications) can go straight to a pull request.

## Conventions

- **Branch names** are lowercase kebab-case with an optional short prefix, for example `feat/core-v0`, `docs/threat-model`, `fix/readme-links`.
- **Commit and PR titles** are concise English in sentence case: an initial capital letter, no final period. For example: `Clarify verifier trust assumptions in README`.
- We do **not** use Conventional Commit prefixes (`feat:`, `fix:`, `chore:`) by default.

## Honesty about security claims

Mithril's credibility depends on never overstating what is verified. Documentation and code comments must not describe target properties as implemented guarantees. When in doubt, say less. See [SECURITY.md](SECURITY.md) and the non-guarantees section of the [README](README.md).
