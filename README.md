# Mithril

> **Status: experimental; no complete compiler backend is implemented — one narrow verifier slice of the Agda-checking backend exists, and no target-code backend exists at all.** This repository currently contains documentation — including the accepted compiler-architecture specification, [`docs/compiler-architecture.md`](docs/compiler-architecture.md) — an experimental Agda semantic spike (`agda/`), the first Mithril Core v0 concrete-syntax checkpoint: a normative JSON Schema plus one handwritten example model, and the Haskell host tool with pinned Haskell CI. The `mithril` CLI supports help and version output plus the four deterministic frontend boundaries, `mithril validate FILE`: JSON parsing, structural validation against the Core v0 schema compiled into the tool from `core/schema.json`, complete Core v0 name resolution — whose success is carried as an explicit internal decoded and name-resolved Core representation rather than raw JSON — complete Core v0 static typing over exactly that representation, and deterministic Core v0 normalization of the well-typed document into an explicit internal typed normalized representation, plus the first consumer of that typed normalized Core: `mithril contract FILE`, which runs the same complete pipeline and then deterministically renders the normalized document as a human-readable security contract for review, plus the first connected verifier slice: `mithril verify FILE`, which runs the same complete pipeline and then — for exactly one supported obligation shape, a document selecting exactly one Acme-derived NoSelfPrivilegeEscalation obligation whose normalized structure corresponds to the mechanized safe `Membership.changeRole` proof rule — generates a deterministic Agda obligation module and has exactly Agda 2.8.0 check it in safe mode against trusted kernel modules embedded into the tool at compile time (VERIFIED, exit 0; every other document, including the canonical Acme example, is UNSUPPORTED, exit 3, and checker problems are tool failures, exit 2, never verdicts). Normalization is structural canonicalization of one authored document only — it preserves authored policy and operand structure and performs no simplification, folding, or evaluation, with `CreateEntity` initializers alone placed in target-attribute declaration order, and it claims no canonical equality between differently authored documents — and contract rendering is deterministic restatement of that normalized document only: it evaluates no policy, compares no two documents (it is not a semantic diff), and its rendered guarantees are explicitly labelled unverified proof obligations. No complete Mithril verifier, policy evaluator, semantic diff, or target generator exists: `validate` and `contract` acceptance neither evaluates policies, nor proves guarantees, nor verifies an application, and `verify` covers exactly one obligation shape. The spike's hand-transcribed application experiment — a NoSelfPrivilegeEscalation proof for a single Acme action inside the fixed-schema Agda kernel ([`agda/README.md`](agda/README.md)) — remains unconnected to the JSON, but its proof rule is now re-proved per supported document by the generated obligation module; the canonical Acme document itself remains unsupported and unverified (its TenantIsolation and AuthenticatedMutation obligations are not implemented), and everything else described below remains unverified.

Mithril is experimental formal-verification infrastructure for **authorization and data-access security in AI-generated web backends**. That is its entire initial scope: it is not a general-purpose verification framework, not a web framework, and not a security product.

## The idea

Humans describe access-control intent in natural language, and that intent is captured in **Mithril Core**, a small, explicit intermediate representation authored as a JSON document. A human may write the JSON directly; an untrusted LLM may optionally propose it. Everything downstream derives from the authored document deterministically, through a single frontend and one shared typed normalized Core:

```
natural-language intent
    │  optional, untrusted human or LLM translation
    ▼
authored Mithril Core JSON
    │  one deterministic frontend (implemented Haskell host tool):
    │  parse → validate → resolve → typecheck → normalize
    ▼
typed normalized Core ──┬──▶ human-readable security contract
                        ├──▶ Agda checking of stated properties
                        └──▶ deterministic generation of Wasp code
```

The key design commitment is that any LLM involvement ends at the authored Core document, and that contract rendering, Agda verification, and target code generation all consume the same typed normalized Core rather than interpreting the JSON independently. Everything downstream of the authored document is intended to be deterministic and auditable, so that what gets checked is exactly what gets executed. Haskell has been selected as the implementation language for this deterministic host tool; today it implements the complete frontend — JSON parsing plus Core v0 structural validation, then complete Core v0 name resolution, then complete Core v0 static typing, then deterministic normalization into the internal typed normalized Core (`mithril validate FILE`) — plus the first of the three consumers: the deterministic human-readable security contract (`mithril contract FILE`), rendered from exactly that typed normalized Core, plus the first slice of the second consumer: `mithril verify FILE`, which connects one supported normalized obligation shape to an independently checked Agda proof through deterministic generation and a process boundary. Nothing else downstream exists: the Agda backend covers exactly that one NoSelfPrivilegeEscalation obligation shape, the target emitter has not been started, the rendered contract is a review artifact, not evaluation, proof, or enforcement, and an unsupported verification outcome establishes nothing. [Wasp](https://wasp.sh/) is the first planned executable target. [`docs/compiler-architecture.md`](docs/compiler-architecture.md) is authoritative for the pipeline and its artifact-ownership boundaries.

### Canonical Haskell commands

The host tool's authoritative build, test, and validation commands, run from the repository root:

```
cabal check
cabal build all --enable-tests
cabal test all --test-show-details=direct
sh test/api-probes/run-api-probes.sh
cabal run mithril -- --help
cabal run mithril -- --version
cabal run mithril -- validate examples/acme/acme.mir.json
cabal run mithril -- contract examples/acme/acme.mir.json
cabal run mithril -- verify test/fixtures/acme-nspe.mir.json
cabal run mithril -- verify examples/acme/acme.mir.json
```

The test suite and the first `verify` command invoke the real Agda 2.8.0 executable, which must be on the search path; the second `verify` command deliberately exits 3 (UNSUPPORTED), because the canonical Acme document lies outside the implemented support rule. The fourth command runs the API-boundary compile-fail probes in two parts. The downstream part builds a probe package that depends on `mithril-ir` as an ordinary external package — its compiling control exercises the complete public pipeline through normalization and on into the public contract API — and proves that importing the hidden document, representation, typechecker, normalized-representation, normalizer, contract-renderer, verifier/planner, embedded-Agda-kernel, and Agda-checker modules, using the `CoreDocument` constructor (including to forge a `Typed` or `Normalized` document), coercing between pipeline stages — including from `Resolved` to `Typed`, from `Typed` to `Normalized`, and from a raw JSON value into a stage — extracting a raw JSON value back out of a resolved document, and passing a merely `Typed` document to the contract renderer or to the public verifier all fail to compile for the intended reasons — which also means external code cannot construct resolved or normalized nodes, typed or normalized documents, mint internal identifiers, or coerce between identifier namespaces, since their types cannot even be named. The in-package part then proves the identifier boundary from inside the tool: flag-gated probe executables of `mithril-ir` itself (with their own compiling control that imports the real internal identifier definitions) attempt cross-namespace `coerce` between global identifier types and must fail with GHC's representation-mismatch error, because the identifier namespaces are distinct data types that not even internal compiler code can coerce into one another. The script needs a POSIX shell in addition to the pinned toolchain.

## Core v0 syntax checkpoint

[`core/schema.json`](core/schema.json) is the first normative concrete-syntax checkpoint for generic Mithril Core v0: a JSON Schema (draft 2020-12) that freezes the external JSON shape of a Core document — schema declarations, term constructors, effects, results, principal modes, and guarantee selections.

It validates JSON shape only. Schema acceptance establishes structural facts (required fields, closed constructor sets, principal-mode surface shape, action classification/effect/result compatibility, and the structural exclusion of direct `Actor` syntax from anonymous policy branches and from `AnyPrincipal` effects and results). It establishes no name resolution, no uniqueness, no typing, no enum-order correctness, no policy evaluation, and no security property.

[`examples/acme/acme.mir.json`](examples/acme/acme.mir.json) is a handwritten example model. It is neither generated nor verified. The three guarantee objects it selects — TenantIsolation, AuthenticatedMutation, and NoSelfPrivilegeEscalation — remain unverified for this document; their appearance in the JSON selects proof obligations and proves nothing. Separately, the Agda spike hand-transcribes the `Membership.changeRole` action and proves its selected NoSelfPrivilegeEscalation case inside the fixed-schema kernel ([`agda/README.md`](agda/README.md)); no tool connects that hand-written proof to this canonical JSON document — `mithril verify` reports this document UNSUPPORTED, and only the dedicated single-obligation fixture reaches a checked proof through generation.

The `mithril` CLI checks this structural conformance, then complete Core v0 name resolution, then complete Core v0 static typing, and then deterministic Core v0 normalization:

```sh
cabal run mithril -- validate examples/acme/acme.mir.json
```

`mithril validate FILE` parses FILE as JSON (rejecting malformed input and trailing garbage), validates it against the canonical schema compiled into the tool from `core/schema.json` within an explicitly gated schema profile (local `#` references only; see the tool's help text for its non-claims — the schema is embedded at build time, so no runtime package-data override such as the `mithril_ir_datadir` environment variable can substitute the grammar; this is provenance by construction, not a cryptographic-integrity claim), then resolves every Core v0 name: declaration names must be unique independently in each namespace — entities, enums, relations, and actions globally; attributes within one entity, endpoints within one relation, parameters within one action — and every name reference must resolve in its correct namespace, including enum values against their enum, action-local `Argument` references, and entity-local `Attribute` members selected through the narrow declared-type lookup that is the only typing-shaped work in that stage. It then typechecks the resolved document completely: term, policy, effect, and result types over the Core v0 value types plus optional relation-payload types; operand compatibility (Bool connectives and allow policies, optional-typed `IsSome`, same-type `Equal` with equality total at every type, ordered-type `LessOrEqual` where ordered means an enum with a declared order — directly or optionally, with absence as bottom); enum-order permutation validity; relation endpoint arity, endpoint entity types, and `SetRelation` payload types; entity-reference `Observe` and `DeleteEntity` targets; `CreateEntity` initializer completeness and value typing; and guarantee well-typedness — a `TenantIsolation` guarantee names one structural access relation (a binary relation whose two distinct designated endpoints cover it, with the subject endpoint of entity type `User`), and its actor-free case terms are typed in their action's environment: the tenant term at exactly the tenant endpoint's entity-reference type, the protected term at `Bool` (a public exception is `protected = false`; the former arbitrary per-case `tenantAccess` policy, which could restate an action's allow policy and collapse the intended obligation to a tautology, no longer exists) — plus `NoSelfPrivilegeEscalation` authority/payload-order agreement and case scope correspondence. The intended (future, still unverified) `TenantIsolation` obligation per case: for every well-formed state and valid request of the case action, if the protected term evaluates true and the request is allowed, the principal is an authenticated user `u` and the access relation contains the tuple binding the subject endpoint to `u` and the tenant endpoint to the evaluated tenant — presence of that tuple is the baseline tenant access, and role floors such as Viewer/Editor/Admin remain in each action's allow policy. Finally it normalizes the well-typed document into the internal typed normalized Core — every term stamped with its determined static type (reusing the typechecker's own judgment, never a second inference), resolved identifiers preserved with names and source paths kept as metadata, enum orders materialized as explicit rankings, lookup and relation-effect endpoint terms bound to their declared endpoints, `CreateEntity` initializers in target-attribute declaration order, principal modes and guarantee structure explicit. A well-typed document always normalizes; normalization introduces no new user-facing rejection. The Acme example passes. Passing establishes JSON shape plus name resolution plus static typing plus deterministic structural normalization only: no complete Mithril verifier or Wasp generator exists, so policy evaluation, general guarantee truth, and every deeper semantic check remain unimplemented (`mithril verify` covers exactly one obligation shape). The typed normalized Core is the single form contract rendering, Agda checking, and the planned target generation must all consume ([`docs/compiler-architecture.md`](docs/compiler-architecture.md)); its implemented consumers are the contract renderer below and the single-obligation verifier slice of `mithril verify`, which checks exactly one structurally gated NoSelfPrivilegeEscalation obligation shape through generated Agda under Agda 2.8.0 — no complete verifier, semantic diff, or target generation exists. Normalization also deliberately does not simplify: no boolean simplification, constant folding, operand reordering, or optimization, and no claim that differently authored but equivalent documents normalize to equal models. A document can therefore validate, resolve, typecheck, and normalize successfully while its guarantees remain unverified proof obligations (`mithril verify`, below, connects exactly one obligation shape to a checked proof; everything else stays unverified). Structural conformance can equally be checked with any standard JSON Schema draft 2020-12 validator; the name-resolution, typing, and normalization stages are specific to the host tool. The separate Agda spike under `agda/` explores candidate kernel semantics; it remains hand-transcribed, is not generated from and does not consume this JSON, and its single application proof does not verify this document.

```sh
cabal run mithril -- contract examples/acme/acme.mir.json
```

`mithril contract FILE` runs exactly the complete validate pipeline and then renders the resulting typed normalized Core as a deterministic, line-oriented, human-readable security contract on stdout: the fixed Mithril Core v0 header and model name, then the entities, enums (every value, with materialized ranks where an order is declared), relations, and actions (parameters, principal mode, classification, allow policies, effect, and result) in normalized declaration order, then the selected guarantees — explicitly labelled unverified proof obligations, with every TenantIsolation access relation and endpoint plus every case term, and every NoSelfPrivilegeEscalation authority component and case scope exposed — and a fixed limitations section. Terms render in an unambiguous, fully parenthesized, constructor-preserving syntax with their stored static types; references render through their resolved identifiers and declaration metadata; the same document always renders to the same bytes regardless of its filesystem path. The contract is the human-review gate of the planned pipeline and nothing more: rendering evaluates no policy, simplifies nothing, proves and checks nothing, compares no two documents (it is not a semantic diff), and generates nothing executable — the rendered guarantees remain unverified proof obligations, exactly as selected. Input failures keep `validate`'s diagnostics and exit classification unchanged.

```sh
cabal run mithril -- verify test/fixtures/acme-nspe.mir.json
```

`mithril verify FILE` runs exactly the complete validate pipeline and then the first connected verifier slice. A pure deterministic support gate inspects the normalized document structurally — stored identities and evidence, never raw JSON bytes, file names, hashes, reparsing, re-resolution, re-inference, or policy evaluation — and accepts exactly one obligation shape: a document selecting exactly one guarantee, a NoSelfPrivilegeEscalation guarantee with exactly one case, whose authority (binary relation, `User` subject endpoint, distinct-entity scope endpoint, two-value declared-order payload enum with absence as bottom), case action (AuthenticatedOnly, exactly the subject/scope/payload parameter list), SetRelation effect bindings and payload, case scope, and allow policy — `And(LessOrEqual(Some(top authority value), Lookup(authority, [Actor, scope])), And(Not(Equal(Actor, subject)), IsSome(Lookup(authority, [subject, scope]))))` — correspond structurally to the safe `Membership.changeRole` proof rule already mechanized in the Agda spike. For a supported document the tool deterministically generates one Agda obligation module from the normalized evidence, materializes it with the trusted kernel modules embedded at compile time into a fresh isolated temporary workspace, and has exactly Agda 2.8.0 check it with `--safe --no-libraries --ignore-interfaces`; when every required named theorem is accepted, the document is VERIFIED (exit 0) — meaning exactly its one selected obligation is checked, nothing more. Every other document is UNSUPPORTED (exit 3) with deterministic sorted reasons, decided before any checker runs: the canonical Acme example (which selects three guarantees; TenantIsolation and AuthenticatedMutation remain unverified), documents selecting no or several guarantees or cases, other actions and effects, and semantically equivalent but differently authored policy shapes. A document selecting no guarantees is never vacuously verified, and the unsafe variant lacking the actor/subject guard is unsupported — not a proved violation: this milestone never emits a violation verdict, and every checker problem (missing or wrong-version Agda, launch or workspace failure, a nonzero check after gate acceptance) is a tool failure with exit 2, never a semantic outcome. The Haskell generator, the embedded Agda kernel modules, the external Agda 2.8.0 toolchain, and the support rule itself are trusted components of this claim. Input failures keep `validate`'s diagnostics and exit classification unchanged.

A successfully resolved document is carried as an explicit internal decoded and name-resolved Core representation — every Core v0 construct an explicit Haskell node, every resolved reference an internal namespace-specific identifier rather than a textual name, and every node and reference retaining its originating JSON path for diagnostics. Generic JSON ends at that internal decode boundary: the raw Aeson value is discarded when resolution succeeds, the representation stays internal to the tool (it is not a public API), and the typechecker and normalizer now consume exactly it — diagnostics point at the retained authored locations. The contract renderer already consumes the normalizer's output exactly that way — resolved identifiers, stored types, materialized ranks, and explicit bindings, never reinterpreted raw JSON and never a rebuilt name resolution or type inference — and the Agda emitter and backend adapters must do the same. The normalized representation is likewise internal: external code cannot import it, construct or forge normalized documents, or recover the internal model from one (the public contract API accepts only the opaque normalized document). None of this changes what the implemented stages establish: well-typedness and normalization are attested only by the opaque stage indexes, the document remains unverified and proves no property, and keeping the schema decoder, the representations' construct coverage, the resolver, the typechecker, and the normalizer aligned with `core/schema.json` remains a manually reviewed obligation, not an automated proof.

Two operational caveats apply to the current tool — known gaps, not contracts: duplicate JSON object members are currently accepted under the JSON parser's (Aeson's) member semantics rather than rejected, and which occurrence wins is not part of any Mithril contract; and no independent input-size, nesting, memory, or execution-resource limits are enforced yet. `mithril validate` should therefore not be treated as hardened validation for arbitrary untrusted, unbounded input. Neither caveat changes the narrower claim above: the unchanged Acme example structurally validates, resolves, typechecks, and normalizes.

## Target properties (not implemented guarantees)

The following are properties Mithril **aims to verify in the future**. No product implementation of them exists, and none of them is guaranteed for any real application:

- **TenantIsolation** — a request executing on behalf of one tenant cannot read or write another tenant's data through generated data-access paths.
- **AuthenticatedMutation** — no generated mutation endpoint is reachable without an authenticated principal.
- **NoSelfPrivilegeEscalation** — no principal can use generated endpoints to raise their own privileges.

Two formal artifacts exist so far. The Agda spike's hand-transcribed, fixed-schema experiment ([`agda/README.md`](agda/README.md)) proves one NoSelfPrivilegeEscalation action/property slice — the Acme `Membership.changeRole` action — inside the kernel, with a checked counterexample for an unsafe variant. And the implemented `mithril verify` slice connects exactly that one obligation shape to an independently checked proof: for a document whose normalized structure the support gate accepts, a generated Agda module re-proves the same rule against the embedded kernel under Agda 2.8.0. Together they cover nothing else: not the complete Acme model, not the canonical JSON document (which remains unsupported), and not the other two properties — no general verifier or general JSON-to-Agda generation exists.

## What Mithril will not guarantee

Even once implemented, Mithril will not make an application "secure" in any general sense, and it will never be reasonable to describe a Mithril-verified backend as unhackable. In particular, Mithril does not and will not address:

- vulnerabilities in code outside the verified policy logic (frontends, custom handlers, third-party dependencies);
- infrastructure, deployment, and operational security (TLS configuration, secret management, database hardening);
- denial of service, side channels, and timing attacks;
- bugs in the trusted computing base: the verifier itself, the code generator, the target framework, and the runtime beneath them;
- the gap between what a human *meant* and what they *stated* — the LLM translation step is explicitly untrusted, and a faithful verification of the wrong intent is still the wrong policy.

Future verification claims will always be scoped to explicitly documented properties under explicitly documented assumptions, as described in [SECURITY.md](SECURITY.md).
