# Mithril

> **Status: experimental; no complete compiler backend is implemented — one narrow verifier slice of the Agda-checking backend exists, and the only target-code backend is one confined Wasp slice of exactly that same verified obligation.** This repository currently contains documentation — including the accepted compiler-architecture specification, [`docs/compiler-architecture.md`](docs/compiler-architecture.md) — an experimental Agda semantic spike (`agda/`), the first Mithril Core v0 concrete-syntax checkpoint: a normative JSON Schema plus one handwritten example model, and the Haskell host tool with pinned Haskell CI. The `mithril` CLI supports help and version output plus the four deterministic frontend boundaries, `mithril validate FILE`: JSON parsing, structural validation against the Core v0 schema compiled into the tool from `core/schema.json`, complete Core v0 name resolution — whose success is carried as an explicit internal decoded and name-resolved Core representation rather than raw JSON — complete Core v0 static typing over exactly that representation, and deterministic Core v0 normalization of the well-typed document into an explicit internal typed normalized representation, plus the first consumer of that typed normalized Core: `mithril contract FILE`, which runs the same complete pipeline and then deterministically renders the normalized document as a human-readable security contract for review, plus the first connected verifier slice: `mithril verify FILE`, which runs the same complete pipeline and then — for exactly one supported obligation family, a document selecting exactly one NoSelfPrivilegeEscalation obligation whose non-empty case collection consists of cases each matching exactly one of two exact structural proof rules, the mechanized safe `Membership.changeRole` change-other rule (rule 1) or the bounded self-update rule (rule 2) — generates a deterministic Agda obligation module with one proof group per case and has exactly Agda 2.8.0 check it in safe mode against trusted kernel modules embedded into the tool at compile time (VERIFIED, exit 0; every other document, including the canonical Acme example, is UNSUPPORTED, exit 3, and checker problems are tool failures, exit 2, never verdicts), plus the first confined target slice: `mithril wasp generate CORE_FILE WASP_ROOT` and `mithril wasp check CORE_FILE WASP_ROOT`, which — after the same pipeline and the verify gate — lower the one shared support plan the verifier consumed, when it is exactly a singleton rule-1 plan (every other verified plan is refused by the Profile-v0 gate before any destination access), into a closed, checked Wasp 0.25.0/PostgreSQL application profile (the Wasp Confinement Profile v0, see below): a normal Wasp application whose every server-capable and security-sensitive input is a managed file regenerated from the typed normalized Core and compared byte-for-byte, deliberately a closed demonstrator and not a general Wasp backend. Normalization is structural canonicalization of one authored document only — it preserves authored policy and operand structure and performs no simplification, folding, or evaluation, with `CreateEntity` initializers alone placed in target-attribute declaration order, and it claims no canonical equality between differently authored documents — and contract rendering is deterministic restatement of that normalized document only: it evaluates no policy, compares no two documents (it is not a semantic diff), and its rendered guarantees are explicitly labelled unverified proof obligations. No complete Mithril verifier, policy evaluator, semantic diff, or general target generator exists: `validate` and `contract` acceptance neither evaluates policies, nor proves guarantees, nor verifies an application, `verify` covers exactly one obligation family (two exact case rules), and the Wasp slice generates exactly its singleton rule-1 form with no semantic-preservation theorem — Wasp, Node, Prisma, PostgreSQL, the templates, and the lowering remain trusted. The spike's hand-transcribed application experiment — a NoSelfPrivilegeEscalation proof for a single Acme action inside the fixed-schema Agda kernel ([`agda/README.md`](agda/README.md)) — remains unconnected to the JSON, but its proof rule is now re-proved per supported document by the generated obligation module; the canonical Acme document itself remains unsupported and unverified (its TenantIsolation and AuthenticatedMutation obligations are not implemented), and everything else described below remains unverified.

Mithril is experimental formal-verification infrastructure for **authorization and data-access security in AI-generated web backends**. That is its entire initial scope: it is not a general-purpose verification framework, not a web framework, and not a security product.

## The idea

Humans describe access-control intent in natural language, and that intent is captured in **Mithril Core**, a small, explicit intermediate representation authored as a JSON document. A human may write the JSON directly; an untrusted LLM may optionally propose it. Everything downstream derives from the authored document deterministically, through a single frontend and one shared typed normalized Core:

```
natural-language intent
    │  optional, untrusted human or LLM translation
    ▼
authored Mithril Core JSON
    │  one deterministic frontend (implemented Haskell host tool):
    │  parse → validate → resolve → typecheck → normalize
    ▼
typed normalized Core ──┬──▶ human-readable security contract
                        ├──▶ Agda checking of stated properties
                        └──▶ deterministic generation of Wasp code
```

The key design commitment is that any LLM involvement ends at the authored Core document, and that contract rendering, Agda verification, and target code generation all consume the same typed normalized Core rather than interpreting the JSON independently. Everything downstream of the authored document is intended to be deterministic and auditable, so that what gets checked is exactly what gets executed. Haskell has been selected as the implementation language for this deterministic host tool; today it implements the complete frontend — JSON parsing plus Core v0 structural validation, then complete Core v0 name resolution, then complete Core v0 static typing, then deterministic normalization into the internal typed normalized Core (`mithril validate FILE`) — plus the first of the three consumers: the deterministic human-readable security contract (`mithril contract FILE`), rendered from exactly that typed normalized Core, plus the first slice of the second consumer: `mithril verify FILE`, which connects one supported normalized obligation family — every case of the one selected NoSelfPrivilegeEscalation guarantee matching one of two exact structural rules — to an independently checked Agda proof through deterministic generation and a process boundary, plus the first slice of the third consumer: `mithril wasp generate|check`, which lowers the singleton rule-1 form of that verified obligation into a closed Wasp 0.25.0 application on PostgreSQL and checks that a source root is exactly that closed profile. Nothing else downstream exists: the Agda backend covers exactly those two NoSelfPrivilegeEscalation case rules, the Wasp emitter covers exactly the singleton rule-1 obligation as a closed demonstrator (not a general backend and with no semantic-preservation theorem), the rendered contract is a review artifact, not evaluation, proof, or enforcement, and an unsupported verification outcome establishes nothing. [Wasp](https://wasp.sh/) is the first executable target. [`docs/compiler-architecture.md`](docs/compiler-architecture.md) is authoritative for the pipeline and its artifact-ownership boundaries.

## Core v0 syntax checkpoint

[`core/schema.json`](core/schema.json) is the first normative concrete-syntax checkpoint for generic Mithril Core v0: a JSON Schema (draft 2020-12) that freezes the external JSON shape of a Core document — schema declarations, term constructors, effects, results, principal modes, and guarantee selections.

It validates JSON shape only. Schema acceptance establishes structural facts (required fields, closed constructor sets, principal-mode surface shape, action classification/effect/result compatibility, and the structural exclusion of direct `Actor` syntax from anonymous policy branches and from `AnyPrincipal` effects and results). It establishes no name resolution, no uniqueness, no typing, no enum-order correctness, no policy evaluation, and no security property.

[`examples/acme/acme.mir.json`](examples/acme/acme.mir.json) is a handwritten example model. It is neither generated nor verified. The three guarantee objects it selects — TenantIsolation, AuthenticatedMutation, and NoSelfPrivilegeEscalation — remain unverified for this document; their appearance in the JSON selects proof obligations and proves nothing. Separately, the Agda spike hand-transcribes the `Membership.changeRole` action and proves its selected NoSelfPrivilegeEscalation case inside the fixed-schema kernel ([`agda/README.md`](agda/README.md)); no tool connects that hand-written proof to this canonical JSON document — `mithril verify` reports this document UNSUPPORTED, and only the dedicated single-obligation fixture reaches a checked proof through generation.

The `mithril` CLI checks this structural conformance, then complete Core v0 name resolution, then complete Core v0 static typing, and then deterministic Core v0 normalization:

```sh
cabal run mithril -- validate examples/acme/acme.mir.json
```

`mithril validate FILE` parses FILE as JSON (rejecting malformed input and trailing garbage), validates it against the canonical schema compiled into the tool from `core/schema.json` within an explicitly gated schema profile (local `#` references only; see the tool's help text for its non-claims — the schema is embedded at build time, so no runtime package-data override such as the `mithril_ir_datadir` environment variable can substitute the grammar; this is provenance by construction, not a cryptographic-integrity claim), then resolves every Core v0 name: declaration names must be unique independently in each namespace — entities, enums, relations, and actions globally; attributes within one entity, endpoints within one relation, parameters within one action — and every name reference must resolve in its correct namespace, including enum values against their enum, action-local `Argument` references, and entity-local `Attribute` members selected through the narrow declared-type lookup that is the only typing-shaped work in that stage. It then typechecks the resolved document completely: term, policy, effect, and result types over the Core v0 value types plus optional relation-payload types; operand compatibility (Bool connectives and allow policies, optional-typed `IsSome`, same-type `Equal` with equality total at every type, ordered-type `LessOrEqual` where ordered means an enum with a declared order — directly or optionally, with absence as bottom); enum-order permutation validity; relation endpoint arity, endpoint entity types, and `SetRelation` payload types; entity-reference `Observe` and `DeleteEntity` targets; `CreateEntity` initializer completeness and value typing; and guarantee well-typedness — a `TenantIsolation` guarantee names one structural access relation (a binary relation whose two distinct designated endpoints cover it, with the subject endpoint of entity type `User`), and its actor-free case terms are typed in their action's environment: the tenant term at exactly the tenant endpoint's entity-reference type, the protected term at `Bool` (a public exception is `protected = false`; the former arbitrary per-case `tenantAccess` policy, which could restate an action's allow policy and collapse the intended obligation to a tautology, no longer exists) — plus `NoSelfPrivilegeEscalation` authority/payload-order agreement and case scope correspondence. The intended (future, still unverified) `TenantIsolation` obligation per case: for every well-formed state and valid request of the case action, if the protected term evaluates true and the request is allowed, the principal is an authenticated user `u` and the access relation contains the tuple binding the subject endpoint to `u` and the tenant endpoint to the evaluated tenant — presence of that tuple is the baseline tenant access, and role floors such as Viewer/Editor/Admin remain in each action's allow policy. Finally it normalizes the well-typed document into the internal typed normalized Core — every term stamped with its determined static type (reusing the typechecker's own judgment, never a second inference), resolved identifiers preserved with names and source paths kept as metadata, enum orders materialized as explicit rankings, lookup and relation-effect endpoint terms bound to their declared endpoints, `CreateEntity` initializers in target-attribute declaration order, principal modes and guarantee structure explicit. A well-typed document always normalizes; normalization introduces no new user-facing rejection. The Acme example passes. Passing establishes JSON shape plus name resolution plus static typing plus deterministic structural normalization only: no complete Mithril verifier and no general Wasp backend exists — the one confined Profile-v0 Wasp adapter of `mithril wasp generate|check` lowers exactly the one verified obligation — so policy evaluation, general guarantee truth, and every deeper semantic check remain unimplemented (`mithril verify` covers exactly one obligation family with two exact case rules). The typed normalized Core is the single form contract rendering, Agda checking, and target generation must all consume ([`docs/compiler-architecture.md`](docs/compiler-architecture.md)); its implemented consumers are the contract renderer below, the single-obligation verifier slice of `mithril verify`, which checks exactly one structurally gated NoSelfPrivilegeEscalation obligation (every selected case matching one of two exact rules) through generated Agda under Agda 2.8.0, and the confined Wasp Confinement Profile v0 adapter of `mithril wasp generate|check`, which lowers the singleton rule-1 form of that same verified obligation from the shared supported normalized NSPE plan — no complete verifier, no semantic diff, and no target generation beyond that one confined slice exists. Normalization also deliberately does not simplify: no boolean simplification, constant folding, operand reordering, or optimization, and no claim that differently authored but equivalent documents normalize to equal models. A document can therefore validate, resolve, typecheck, and normalize successfully while its guarantees remain unverified proof obligations (`mithril verify`, below, connects exactly one obligation family — two exact case rules — to checked proofs; everything else stays unverified). Structural conformance can equally be checked with any standard JSON Schema draft 2020-12 validator; the name-resolution, typing, and normalization stages are specific to the host tool. The separate Agda spike under `agda/` explores candidate kernel semantics; it remains hand-transcribed, is not generated from and does not consume this JSON, and its single application proof does not verify this document.

```sh
cabal run mithril -- contract examples/acme/acme.mir.json
```

`mithril contract FILE` runs exactly the complete validate pipeline and then renders the resulting typed normalized Core as a deterministic, line-oriented, human-readable security contract on stdout: the fixed Mithril Core v0 header and model name, then the entities, enums (every value, with materialized ranks where an order is declared), relations, and actions (parameters, principal mode, classification, allow policies, effect, and result) in normalized declaration order, then the selected guarantees — explicitly labelled unverified proof obligations, with every TenantIsolation access relation and endpoint plus every case term, and every NoSelfPrivilegeEscalation authority component and case scope exposed — and a fixed limitations section. Terms render in an unambiguous, fully parenthesized, constructor-preserving syntax with their stored static types; references render through their resolved identifiers and declaration metadata; the same document always renders to the same bytes regardless of its filesystem path. The contract is the human-review gate of the planned pipeline and nothing more: rendering evaluates no policy, simplifies nothing, proves and checks nothing, compares no two documents (it is not a semantic diff), and generates nothing executable — the rendered guarantees remain unverified proof obligations, exactly as selected. Input failures keep `validate`'s diagnostics and exit classification unchanged.

```sh
cabal run mithril -- verify test/fixtures/acme-nspe.mir.json
```

`mithril verify FILE` runs exactly the complete validate pipeline and then the first connected verifier slice. A pure deterministic support gate inspects the normalized document structurally — stored identities and evidence, never raw JSON bytes, file names, hashes, reparsing, re-resolution, re-inference, or policy evaluation — and accepts exactly one obligation family: a document selecting exactly one guarantee, a NoSelfPrivilegeEscalation guarantee whose authority is a binary relation with a `User` subject endpoint, a distinct-entity scope endpoint, and a two-value declared-order payload enum with absence as bottom, and whose non-empty case collection consists entirely of cases each matching exactly one of two exact structural proof rules, classified independently and in authored order (never only the first case, never with a case dropped, reordered, or deduplicated). Rule 1, change-other: an AuthenticatedOnly action with exactly the subject/scope/payload parameter list, a SetRelation effect binding subject, scope, and payload to exactly those parameters, a case scope of exactly the scope parameter, and the allow policy `And(LessOrEqual(Some(top authority value), Lookup(authority, [Actor, scope])), And(Not(Equal(Actor, subject)), IsSome(Lookup(authority, [subject, scope]))))` — the safe `Membership.changeRole` proof rule already mechanized in the Agda spike. Rule 2, bounded self-update: an AuthenticatedOnly action with exactly the scope/payload parameter list, a SetRelation effect binding the subject endpoint to exactly `Actor`, the scope endpoint to the scope parameter, and the payload to the payload parameter, a case scope of exactly the scope parameter, and the allow policy exactly `LessOrEqual(Some(payload), Lookup(authority, [Actor, scope]))` — with no further conjunct (an explicit `IsSome` is redundant under absence as bottom and is deliberately not accepted). The two rules are disjoint by declared arity, so no case can match both; a case matching neither makes the whole obligation UNSUPPORTED with reasons anchored at the offending case, action, parameter, policy, effect, or case-scope site. For a supported document the tool deterministically generates one Agda obligation module from the normalized evidence — one complete proof group per case (for rule 1 the case-scope, actor-distinctness, actor-authority-unchanged, and no-self-escalation theorems; for rule 2 the case-scope, policy-bounds-payload, actor-authority-written, and no-self-escalation theorems), each case in its own inner module qualified by its zero-based authored position together with its own checked manifest, while a singleton rule-1 document keeps the original flat module byte-for-byte — materializes it with the trusted kernel modules embedded at compile time into a fresh isolated temporary workspace, and has exactly Agda 2.8.0 check it with `--safe --no-libraries --ignore-interfaces`; when every required named theorem of every case is accepted, the document is VERIFIED (exit 0) — meaning exactly the selected cases of its one selected obligation are checked, nothing more: no other guarantee, action, or unselected authority writer. The singleton rule-1 report is unchanged; a multi-case (or singleton rule-2) report lists every case in authored order with its position, rule, action, and checked theorem names. Every other document is UNSUPPORTED (exit 3) with deterministic sorted reasons, decided before any checker runs: the canonical Acme example (which selects three guarantees; TenantIsolation and AuthenticatedMutation remain unverified), documents selecting no or several guarantees, other actions and effects, and semantically equivalent but differently authored policy shapes. A document selecting no guarantees is never vacuously verified, and both the unsafe variant lacking the actor/subject guard and the dangerous mutation that additionally lowers the privilege floor — a genuine self-promotion counterexample — are unsupported, not proved violations: this milestone never emits a violation verdict, and every checker problem (missing or wrong-version Agda, launch or workspace failure, a nonzero check after gate acceptance) is a tool failure with exit 2, never a semantic outcome. The Haskell generator, the embedded Agda kernel modules, the external Agda 2.8.0 toolchain, and the support rules themselves are trusted components of this claim. Input failures keep `validate`'s diagnostics and exit classification unchanged.

```sh
cabal run mithril -- wasp generate test/fixtures/acme-nspe.mir.json /path/to/new/root
cabal run mithril -- wasp check test/fixtures/acme-nspe.mir.json test/fixtures/wasp-acme
```

`mithril wasp generate CORE_FILE WASP_ROOT` and `mithril wasp check CORE_FILE WASP_ROOT` implement the first confined target slice, the **Wasp Confinement Profile v0**, for exactly the singleton rule-1 (change-other) obligation. Both run the complete validate pipeline, require the production verifier to report the document VERIFIED (the canonical Acme example is UNSUPPORTED to them as well, exit 3, with the verifier's own reasons), require the shared tagged plan to be exactly one rule-1 case — the Profile-v0 capability gate refuses a singleton rule-2 plan and every multi-case plan, including the verified two-case fixture `test/fixtures/acme-nspe-self-update.mir.json`, with a deterministic source-anchored reason (exit 3) before any destination is resolved, inspected, staged, backed up, or written — and then lower the same shared NoSelfPrivilegeEscalation support plan the verifier consumed — the supported-shape classification and every ranking fact (the materialized ranking, its bottom and top with their validated numeric ranks, the absent rank) are stated once, in a package-private facility both backends read, and the emitter restates none of it — into a normal Wasp 0.25.0 application on PostgreSQL. Every identifier, filename, and route of the bundle is a fixed target name derived from the role a declaration plays in the supported shape (`MithrilSubject`, `MithrilScope`, `MithrilAuthority`, `MithrilPayload`, the Action `mithrilCaseAction` at `POST /operations/mithril-case-action`) or from the canonical position of an enum value (`Value0`, `Value1`), never an authored name: a scope entity named `String` or `Session`, reserved words, acronyms, and authored names spelled like the target names all render and compile (the committed variants under `test/fixtures/wasp-renames` pin this), the inventory is the same for every supported document, and authored names survive only as escaped comments, string metadata, and the manifest's explicit authored-to-target mapping. The generated bundle is closed: `main.wasp.ts` (Wasp username-and-password authentication, one route and page, exactly one authenticated Action), `schema.prisma` (the PostgreSQL datasource, the subject and scope entities, the authority relation with a composite identity over its endpoint fields and the authority enum as its payload column), the generated TypeScript Action (`src/mithrilCaseAction.ts`), `package.json` (Wasp's required dependencies and nothing else — the Prisma runtime is the one Wasp supplies; no separate ORM or database client), the TypeScript and Vite configuration, the Wasp root marker, the fixed-bytes Mithril ownership marker `.mithril-wasp-profile`, `.gitignore`, `.npmrc`, a minimal static client shell, and the deterministic manifest `mithril.manifest.json` — fourteen managed files. The Action requires Wasp authentication and uses `context.user.id` as its only identity, validates the target, scope, and payload arguments (400), reads the actor's and the target's authority tuples and performs the authorized `SetRelation` update inside one Prisma interactive transaction at `Serializable` isolation, denies with one uniform 403 whenever the actor's materialized rank is below the floor, the actor is the target, or the target tuple is absent (so denials leak no existence information), retries Prisma `P2034` conflicts a fixed three attempts before a 409, maps every other failure to a stable 500, and uses no raw SQL. Its finite role ranking is exactly the materialized enum ranking stored in the normalized Core as validated by the shared plan; the emitter derives no ordering of its own. The pure renderer (`Mithril.Core.Wasp.renderWaspBundle`) establishes supported-shape lowering only — no rendered byte claims verification; the VERIFIED provenance belongs to the `generate` and `check` commands, which require the production verifier to report VERIFIED before rendering and say so in their reports.

The confinement boundary is precise. `check` performs no writes: it validates the snapshot it takes (no duplicate, aliased, absolute, or dot-relative entry), walks the complete source root without following symbolic links, rejects hard-linked files (link count above one), compares every managed file byte-for-byte with the freshly regenerated bundle, and rejects every missing, altered, or unexpected input — any additional `*.wasp.ts` file, any other server-capable source file, a second Action, Query, API, CRUD, job, seed, server setup, or middleware path, an import of `prisma` from `wasp/server` anywhere but the generated Action, an import of `@prisma/client`, `pg`, or another driver or ORM, raw SQL or Prisma raw-query APIs, `eval`, `Function` construction, dynamic `import`, `child_process`, dependency or database-provider drift, symbolic and hard links and other path escapes, and installation, build, migration, lockfile, and environment outputs inside the root — with deterministic, sorted, deduplicated diagnostics (exit 4). The authority is the regenerated closed path inventory plus exact bytes for every managed file; the denylist scan only labels *why* an already-rejected file is dangerous and is never sufficient on its own. `generate` renders the complete bundle before touching the filesystem, accepts the root path lexically only (an empty, `.`, or `..` component — a trailing separator included — is refused, never normalized), inspects every ancestor and the root with no-follow metadata (a symbolic link or non-directory anywhere refuses; exit 1), refuses an existing entry of any kind at the backup sibling path `WASP_ROOT.mithril-wasp-backup` without touching it (exit 1), and installs the bundle as a complete root: an absent or empty destination is initialized; a nonempty destination is replaced as a whole only when it carries the byte-exact ownership marker and nothing outside the fixed inventory (altered or missing managed files are recovered by the replacement); an unmarked nonempty root or any unmanaged path is refused without mutation (exit 4). The new bundle is staged in a sibling directory created atomically with the private permission bits 0700 (whatever the umask; the installed root is that same directory and keeps the mode, so other unprivileged users cannot traverse it — nothing is claimed against privileged users or a malicious process of the same user), checked there, and — after the destination and its ancestors are revalidated and the backup path is confirmed absent a second time — swapped into place by whole-directory renames, the previous root moved to a sibling backup that is restored if the swap fails and removed only after the new root is installed, so every failure leaves the complete old or the complete new root and names any directory left behind; `generate` then finishes with exactly the same check. The committed fixture `test/fixtures/wasp-acme` is the reviewed golden output of `generate` for the supported fixture — regenerated only through the tool, never hand-edited — and the test suite pins that a fresh bundle equals it byte-for-byte, that rendering is independent of the Core file's path and of the target root, that the verifier and the emitter consume one plan (every materiality mutation of the verifier's table is replayed against the emitter, and an independent oracle read from the authored JSON agrees with both the generated Agda module and the manifest), that every plan field is classified in an explicit consumption inventory (most are consumed by both backends; the declared members, the full ranking, the absent rank, and the effect and case-scope bindings by the emitter only) with field-specific mutations and expected output fragments, that malformed normalized evidence fails closed before anything is generated, that no rendered byte claims verification, that every committed rename variant renders with the fixed inventory and identifiers, the installation semantics above under injected faults (stale staging or backup directories, a failed swap with and without a successful rollback, a root or ancestor replaced by a link or a file before the final revalidation, a read-only parent), and an exact confinement attack matrix in which every bypass fails `check` before any Wasp step could run.

What this slice is not: it is a deliberately closed demonstrator, not a claim that Mithril generates arbitrary complete products — not a general Wasp backend, not a whole-product generator, not a complete verifier, and not a runtime sandbox. No semantic-preservation theorem between the Core semantics and the generated TypeScript exists; Wasp 0.25.0, Node, Prisma, PostgreSQL, the templates, and the lowering are trusted components of every claim about the generated application. The confinement claim is exactly that the source root the checker walked was, at the time of checking or generation, a valid clean source snapshot (repository-authored alternate server paths are rejected; hard-linked inputs are rejected). Outside the claim, unless separately prevented: malicious concurrent same-user mutation after the final check (the validation is path-based, not descriptor-relative; POSIX no-follow metadata and mode-requesting directory creation from the `unix` package, Linux being the exercised platform), privileged users and malicious same-user processes in general (the private 0700 staging and root directories keep other unprivileged users out, and nothing more), malicious changes to the checker or the CI that runs it, compromise of the Wasp, Node, Prisma, or PostgreSQL dependencies, external processes holding the database credentials, and any tampering after `wasp build` (in `.wasp/`, `node_modules/`, the deployed bundle, or the database itself). Everything previously unverified stays unverified — TenantIsolation, AuthenticatedMutation, unsupported Core shapes, semantic diff, general JSON-to-Agda generation, and every other target.


A successfully resolved document is carried as an explicit internal decoded and name-resolved Core representation — every Core v0 construct an explicit Haskell node, every resolved reference an internal namespace-specific identifier rather than a textual name, and every node and reference retaining its originating JSON path for diagnostics. Generic JSON ends at that internal decode boundary: the raw Aeson value is discarded when resolution succeeds, the representation stays internal to the tool (it is not a public API), and the typechecker and normalizer now consume exactly it — diagnostics point at the retained authored locations. The contract renderer already consumes the normalizer's output exactly that way — resolved identifiers, stored types, materialized ranks, and explicit bindings, never reinterpreted raw JSON and never a rebuilt name resolution or type inference — and the Agda emitter and backend adapters must do the same. The normalized representation is likewise internal: external code cannot import it, construct or forge normalized documents, or recover the internal model from one (the public contract API accepts only the opaque normalized document). None of this changes what the implemented stages establish: well-typedness and normalization are attested only by the opaque stage indexes, the document remains unverified and proves no property, and keeping the schema decoder, the representations' construct coverage, the resolver, the typechecker, and the normalizer aligned with `core/schema.json` remains a manually reviewed obligation, not an automated proof.

Two operational caveats apply to the current tool — known gaps, not contracts: duplicate JSON object members are currently accepted under the JSON parser's (Aeson's) member semantics rather than rejected, and which occurrence wins is not part of any Mithril contract; and no independent input-size, nesting, memory, or execution-resource limits are enforced yet. `mithril validate` should therefore not be treated as hardened validation for arbitrary untrusted, unbounded input. Neither caveat changes the narrower claim above: the unchanged Acme example structurally validates, resolves, typechecks, and normalizes.

## Target properties (not implemented guarantees)

The following are properties Mithril **aims to verify in the future**. No product implementation of them exists, and none of them is guaranteed for any real application:

- **TenantIsolation** — a request executing on behalf of one tenant cannot read or write another tenant's data through generated data-access paths.
- **AuthenticatedMutation** — no generated mutation endpoint is reachable without an authenticated principal.
- **NoSelfPrivilegeEscalation** — no principal can use generated endpoints to raise their own privileges.

Two formal artifacts exist so far, plus one confined executable counterpart (the Wasp Confinement Profile v0 of the same obligation, which carries no semantic-preservation theorem). The Agda spike's hand-transcribed, fixed-schema experiment ([`agda/README.md`](agda/README.md)) proves one NoSelfPrivilegeEscalation action/property slice — the Acme `Membership.changeRole` action — inside the kernel, with a checked counterexample for an unsafe variant. And the implemented `mithril verify` slice connects that obligation shape — and the bounded self-update shape, an authenticated principal updating its own authority to a payload bounded by its pre-state authority — to independently checked proofs: for a document whose normalized structure the support gate accepts, a generated Agda module re-proves the matching rule for every selected case against the embedded kernel under Agda 2.8.0. Together they cover nothing else: not the complete Acme model, not the canonical JSON document (which remains unsupported), and not the other two properties — no general verifier or general JSON-to-Agda generation exists.

## What Mithril will not guarantee

Even once implemented, Mithril will not make an application "secure" in any general sense, and it will never be reasonable to describe a Mithril-verified backend as unhackable. In particular, Mithril does not and will not address:

- vulnerabilities in code outside the verified policy logic (frontends, custom handlers, third-party dependencies);
- infrastructure, deployment, and operational security (TLS configuration, secret management, database hardening);
- denial of service, side channels, and timing attacks;
- bugs in the trusted computing base: the verifier itself, the code generator, the target framework, and the runtime beneath them;
- the gap between what a human *meant* and what they *stated* — the LLM translation step is explicitly untrusted, and a faithful verification of the wrong intent is still the wrong policy.

Future verification claims will always be scoped to explicitly documented properties under explicitly documented assumptions, as described in [SECURITY.md](SECURITY.md).
