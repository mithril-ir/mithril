# Guidelines for coding agents working on Mithril

This file is operational guidance for AI coding agents (and useful context for humans supervising them). It is repository-specific; follow it over generic defaults.

## What this project is

Mithril is experimental formal-verification infrastructure for authorization and data-access security in AI-generated web backends. Intended flow: natural-language intent → authored Mithril Core JSON (written by a human, optionally proposed by an untrusted LLM) → one deterministic Haskell frontend → typed normalized Core → human-readable contract, Agda checking, and deterministic Wasp generation. `docs/compiler-architecture.md` is authoritative for this pipeline and for artifact ownership.

**Current status: the four frontend boundaries, the deterministic contract renderer, one deliberately narrow connected verifier slice, and one confined Wasp target slice of exactly the same verified obligation — and nothing beyond them — are implemented.** The repository contains documentation (including the accepted compiler-architecture specification, `docs/compiler-architecture.md`), repository configuration, an experimental Agda semantic spike under `agda/` (see `agda/README.md`) — an exploratory mechanization of candidate kernel semantics that neither selects Agda as the implementation language nor constitutes a product prototype — the Core v0 concrete-syntax checkpoint described below, and the Haskell host tool with pinned Haskell CI: Cabal package `mithril-ir`, whose `mithril` CLI prints help and version output and implements `mithril validate FILE` — deterministic JSON parsing, structural Core v0 validation of a document against the canonical `core/schema.json` compiled into the tool at build time, complete Core v0 name resolution, whose success is carried as an explicit internal decoded and name-resolved Core representation (identifier-based references with JSON source paths; generic JSON ends at the internal decode boundary), complete Core v0 static typing over exactly that representation, and deterministic Core v0 normalization of the well-typed document into a distinct explicit internal typed normalized representation (statically typed terms, materialized enum ranks, explicit endpoint bindings, declaration-ordered `CreateEntity` initializers, explicit guarantee structure) — `mithril contract FILE`, the same complete pipeline followed by deterministic rendering of the normalized document as a line-oriented, human-readable security contract (the first consumer of the typed normalized Core; byte-frozen golden outputs), and `mithril verify FILE`, the same complete pipeline followed by the first connected verifier slice: a pure deterministic support gate over the normalized document and, for exactly one supported obligation family — a document selecting exactly one NoSelfPrivilegeEscalation obligation whose non-empty case collection consists of cases each matching exactly one of two exact structural proof rules, the mechanized safe `Membership.changeRole` change-other rule (rule 1) or the bounded self-update rule (rule 2) — a deterministically generated Agda obligation module with one proof group per case, checked by exactly Agda 2.8.0 in safe mode against trusted kernel modules embedded at compile time (VERIFIED, exit 0; everything else UNSUPPORTED, exit 3, with checker problems classified as tool failures, exit 2, never as verdicts) — and `mithril wasp generate CORE_FILE WASP_ROOT` / `mithril wasp check CORE_FILE WASP_ROOT`, the same pipeline and verify gate followed by deterministic lowering of the one shared NoSelfPrivilegeEscalation support plan into a closed, checked Wasp 0.25.0/PostgreSQL application profile selected by the plan's ordered rule tags — the Wasp Confinement Profile v0 for exactly a singleton rule-1 plan (golden fixture `test/fixtures/wasp-acme`), the Wasp Confinement Profile v1 for exactly the ordered rule-1, rule-2 case pair (golden fixture `test/fixtures/wasp-acme-self-update`); every other verified plan is refused by the profile dispatcher before any destination access — with unit tests, process-level CLI tests, and downstream plus in-package API-boundary compile-fail probes over these boundaries, and a separate pinned CI job for the real Wasp/PostgreSQL vertical battery. Validation, resolution, typing, and normalization establish JSON shape conformance, name resolution, static well-typedness, and deterministic structural normalization only; normalization preserves authored policy and operand structure and performs no simplification, folding, or evaluation — `CreateEntity` initializers alone are placed in target-attribute declaration order — and claims no canonical equality between differently authored documents; contract rendering deterministically restates the normalized document for human review and nothing more — it evaluates no policy and is not a semantic diff. The verifier slice verifies exactly the selected cases of the one supported obligation of a supported document and nothing else: the canonical Acme example remains unsupported and unverified (its TenantIsolation and AuthenticatedMutation obligations are not implemented), an unsafe variant and a dangerous self-promotion mutation are unsupported rather than proved violations, no policy is evaluated, no counterexample is produced, and no other guarantee, action, or unselected authority writer is established or proved. The Wasp slices generate exactly the singleton rule-1 form (Profile v0) and exactly the ordered rule-1, rule-2 pair (Profile v1) of that same obligation as closed demonstrators — arbitrary multi-case lowering is not implemented, and every other verified case sequence is refused by the dispatcher — with no semantic-preservation theorem (a rendered bundle is trusted correspondence evidence, not a proof): not a general Wasp backend, not a whole-product generator, not a complete verifier, not a runtime sandbox.

## Core v0 concrete syntax

- `core/schema.json` (JSON Schema, draft 2020-12) is the source of truth for the current external JSON shape of a Mithril Core v0 document.
- `examples/acme/acme.mir.json` is a handwritten source example. Neither file is generated; both are edited by hand.
- Schema acceptance is structural validation only — required fields, closed constructor sets, principal-mode surface shape, classification/effect/result compatibility. It is not semantic validation and not proof: declaration uniqueness, name resolution, static typing, enum-order permutation validity, and normalization are now established by the host tool's implemented resolver, typechecker, and normalizer stages, while policy evaluation and general guarantee verification still require the later complete verifier, which does not exist — the implemented `mithril verify` slice checks exactly one supported NoSelfPrivilegeEscalation obligation family (every case of the one selected guarantee matching one of two exact structural rules) and nothing else.
- Haskell is the selected implementation language for the deterministic host tool (see `docs/compiler-architecture.md`). The host tool now implements the four frontend boundaries — `mithril validate FILE`: JSON parsing, structural validation against this schema, complete Core v0 name resolution, complete Core v0 static typing, and deterministic Core v0 normalization — plus the deterministic contract renderer over their result (`mithril contract FILE`), plus the single-obligation verifier slice (`mithril verify FILE`; see the decided-architecture bullet below for its exact scope), plus the confined Wasp slices of that same obligation (`mithril wasp generate|check`, Profiles v0 and v1; their own bullet below), and nothing after those: no complete verifier and no general emitter exists. `Typed` is an opaque stage attestation about names and static types; `Normalized` is the opaque attestation that the well-typed document was additionally normalized into the explicit typed normalized Core representation — structural canonicalization of one authored document, not evaluation, not verification — and the rendered contract is a deterministic restatement of that representation for human review, not evaluation, not a semantic diff, and not proof.
- The Agda spike under `agda/` remains a separate exploration; it does not consume this JSON. It contains one hand-transcribed application slice — a checked NoSelfPrivilegeEscalation case for `Membership.changeRole` (see `agda/README.md`) — which does not establish the JSON document's guarantees. Five of its modules (`Base`, `Core`, `Policy`, `Effect`, `Guarantee`) now additionally serve as the trusted generic kernel the implemented verifier slice embeds at compile time and materializes into isolated checking workspaces; the hand-written `Mithril.Acme` slice itself is never imported by generated code.

## Hard rules

1. **No Git or GitHub operations.** Do not commit, branch, merge, rebase, push, tag, or open/modify pull requests, issues, or releases. The human operates version control.
2. **No unrequested scope expansion.** Do exactly what was asked. Do not add source directories, package manifests, CI workflows, architecture documents, templates, or "helpful" extras that were not requested.
3. **No arbitrary escape hatches inside verified policy logic.** Once implementation exists, verified policy logic must never embed arbitrary JavaScript, raw SQL, FFI calls, or other unanalyzable code. Anything the verifier cannot reason about does not belong inside the verified boundary.
4. **No unchecked proof escape hatches for claimed guarantees.** Never use `postulate`, `unsafe`, `assume`, `admit`, `sorry`, or equivalent mechanisms to make a claimed guarantee check. An axiom needed for a documented, reviewed trusted-computing-base assumption is a human decision, not something an agent introduces to make a build pass.
5. **Never hand-edit generated files.** Once code generation exists, generated artifacts are modified only by changing their source and regenerating. If a generated file looks wrong, fix the generator or the input, and say so.
6. **Do not overstate security.** Documentation and code you write must describe TenantIsolation, AuthenticatedMutation, and NoSelfPrivilegeEscalation (and any future properties) as targets until they are actually verified, and must never claim general security.

## Decided architecture — follow it

The following decisions are made and documented. Do not re-open them, contradict them, or describe them as undecided.

- **Haskell is the selected implementation language** for the deterministic host tool: the CLI, the frontend stages (conceptually `Raw -> Resolved -> Typed -> Normalized`), the contract renderer, and the backend emitters. Agda remains the separate formal backend/checker, reached through generated files and a process boundary — the Haskell decision does not make Haskell the proof backend, and the host tool must not import or depend on Agda compiler internals as a Haskell library.
- **The Haskell toolchain configuration is fixed.** GHC 9.12.4, cabal-install 3.18.1.0, and the GHC2021 language edition are the supported configuration. The canonical commands, run from the repository root, are `cabal check`, `cabal build all --enable-tests`, `cabal test all --test-show-details=direct` (the test suite's verifier checks invoke the real Agda 2.8.0 executable, which must be on the search path), `sh test/api-probes/run-api-probes.sh` (the API-boundary compile-fail probes — the downstream package attacks plus the in-package identifier non-coercion attacks; requires a POSIX shell), `cabal run mithril -- --help`, `cabal run mithril -- --version`, `cabal run mithril -- validate examples/acme/acme.mir.json`, `cabal run mithril -- contract examples/acme/acme.mir.json`, `cabal run mithril -- verify test/fixtures/acme-nspe.mir.json` (the supported singleton rule-1 fixture; exit 0), `cabal run mithril -- verify test/fixtures/acme-nspe-self-update.mir.json` (the supported two-case rule-1/rule-2 fixture; exit 0), `cabal run mithril -- verify test/fixtures/acme-nspe-dangerous.mir.json` (the dangerous self-promotion mutation; deliberately UNSUPPORTED with exit 3, never a verdict), `cabal run mithril -- verify examples/acme/acme.mir.json` (the canonical document; deliberately UNSUPPORTED with exit 3), `cabal run mithril -- wasp check test/fixtures/acme-nspe.mir.json test/fixtures/wasp-acme` (the committed Profile-v0 fixture is exactly the fresh bundle; exit 0), and `cabal run mithril -- wasp check test/fixtures/acme-nspe-self-update.mir.json test/fixtures/wasp-acme-self-update` (the committed Profile-v1 fixture; exit 0). Do not add dependencies and do not select packaging or distribution mechanisms without an explicit task.
- **The name-resolution boundary is implemented.** After structural validation, `Mithril.Core.Resolution.resolveCoreDocument` enforces declaration-name uniqueness independently per namespace (entities, enums, relations, and actions globally; attributes, endpoints, and parameters per owner) and resolves every Core v0 name reference in its correct namespace, including the narrow declared-type lookup that selects the entity-local attribute namespace of an `Attribute` projection — the only typing-shaped judgment in the stage — and records its one designation of the distinguished `User` entity (the unique entity declaration carrying the schema-designated name, taken from the same entity-namespace lookup that resolves every `Actor` term) in the resolved model as `modelUserEntity`, so later stages propagate that identity instead of selecting a `User` by name again. `Resolved` attests names only — static typing is the next implemented boundary (below), and policy evaluation and guarantee verification remain unimplemented — so a resolved document can still fail the typechecker. Deterministic maps and sets come from the direct `containers` dependency (`>= 0.7 && < 0.8`, resolves 0.7, BSD-3-Clause, a GHC boot library, part of the trusted computing base). User name errors exit 1; internal resolver-invariant failures (schema/resolver drift after successful structural validation) are classified separately and exit 2 — with the schema compiled in, no public invocation can construct these internal states, so their classification and rendering are pinned by unit tests over the pure seam. `Resolved` now carries the explicit internal decoded and name-resolved Core representation: the frontend decodes the structurally valid JSON — in one interpretation shared between its internal schema decoder and the resolver — into explicit Haskell nodes whose resolved references are namespace-specific internal identifiers (owner-local identifiers embed their owner) with declaration names kept only as diagnostic metadata, and every node and reference retains its originating JSON path. The raw JSON value is discarded at that internal decode boundary; the representation is hidden inside the package — it lives in a package-private sublibrary (an internal testability and encapsulation mechanism, not a packaging decision): the production public library depends on it and consumes the representation from it, the package's own white-box test suite and in-package probes may also depend on it, and no external package can depend on it or import its modules — so external code cannot construct its nodes, mint or coerce identifiers, or extract JSON from a resolved document, and the identifier namespaces are distinct data types that even in-package code cannot coerce into one another. The implemented typechecker and normalizer consume exactly this representation — never generic Aeson `Value` — the implemented contract renderer consumes exactly the normalizer's output the same way, and the Agda emitter and backend adapters must do likewise, without independently reinterpreting raw JSON or rebuilding name resolution. The representation is not typed normalized Core: whether it is well-typed is attested only by the separate `Typed` stage index, normalization constructs a distinct normalized model from it, and it remains unverified and proves no property.
- **The static-typing boundary is implemented.** After name resolution, `Mithril.Core.Typing.typecheckCoreDocument` checks every Core v0 static-typing judgment over the explicit resolved representation — and only over it: no raw JSON is reread, no name resolution is rebuilt, and no `User` is selected by name — the resolver-stored distinguished-`User` identity is validated against the declaration it names (present at its canonical position with its own identifier, carrying the schema-designated name, no other declaration carrying it; any drift is an internal invariant, never a re-selection) and carried in the typing signature. The type language is the four value types (`Bool`, `Unit`, `Enum E`, `EntityRef E`) plus one-level optional types over them for relation-payload presence. The judgments: term, policy, effect, and result typing; operand compatibility (`And`/`Or`/`Not` and every allow policy at `Bool`; `IsSome` over an optional type; `Equal` over two operands of one type, with equality total at every type; `LessOrEqual` over two operands of one ordered type — an enum with a declared order, directly or under the optional level with absence as bottom, mirroring the Agda spike's candidate semantics); enum-order complete-permutation validity; relation endpoint arity and per-position endpoint entity types at `Lookup`, `SetRelation`, and `RemoveRelation` sites plus `SetRelation` payload typing; entity-reference `Observe` and `DeleteEntity` targets; `CreateEntity` initializer completeness and value typing; and guarantee well-typedness — `TenantIsolation` guarantees whose structural `access` relation is binary with two distinct designated endpoints (which therefore cover it) and a subject endpoint of entity type `User`, and whose actor-free case terms are typed in their action's environment (a `tenant` of exactly the tenant endpoint's entity-reference type, a `Bool` `protected`; presence of a `(subject, tenant)` tuple in the access relation is the baseline tenant access of the still-unverified obligation — role floors stay in action allow policies, and the former arbitrary per-case `tenantAccess` policy no longer exists), and `NoSelfPrivilegeEscalation` authorities whose subject endpoint references the distinguished `User` entity, whose subject and scope endpoints are distinct and cover the relation's endpoints, whose relation payload is exactly the declared-order `payloadOrder` enum, and whose case scope terms correspond one-to-one, at the scope endpoint's entity type, with the authority's scope endpoints. Typing diagnostics are deterministic — authored JSON-pointer locations from the representation's retained source paths, aggregated across independent sites, sorted, deduplicated, dependent cascades suppressed — and exit 1; shapes of the resolved model the typechecker cannot interpret are impossible after successful resolution, are classified as internal typechecker-invariant errors with exit 2 (unconstructible through any public invocation; classification and rendering pinned by white-box tests over the pure seam), and dominate. The stage adds no dependency and no second representation: `StagePayload Typed` is the same explicit resolved model, the `Typed` index is the attestation, and external code can neither construct a typed document, nor coerce `Resolved` to `Typed`, nor import the internal typechecker module (all pinned by compile-fail probes). `Typed` attests static well-typedness only: it is not normalization, not policy evaluation, not guarantee truth, and not verification — a well-typed document's guarantees remain unverified proof obligations.
- **The normalization boundary is implemented.** After static typing, `Mithril.Core.Normalization.normalizeCoreDocument` accepts exactly a `CoreDocument Typed` — the stage indexes make anything earlier unacceptable — and constructs the explicit typed normalized Core representation: a distinct package-private model (`Mithril.Core.Internal.Normalized`, in the same private sublibrary as the resolved representation, alongside the shared static type language `Mithril.Core.Internal.StaticType`), never the resolved model under another stage tag. Normalization stamps every term with the static type the typechecker determined — the normalizer reuses the typechecker's shared internal elaboration/type-query facility (`inferValue`/`inferPolicy` over the model `Signature`, plus its ordered-comparison classification, built like the declared-type projections on the shared static-type module) and restates no typing, projection, or classification rule, so each of those judgments has exactly one statement and later backends never rerun type inference; it preserves every resolved namespace-specific identifier while keeping declaration names and source paths as diagnostic/rendering metadata that never determines semantic linkage; it materializes declared enum orders into explicit complete rankings and records each `LessOrEqual`'s ordered reading (which enum ranks it, and whether at the absence-as-bottom optional level); it pairs lookup and relation-effect endpoint terms one-to-one with the declared endpoints they bind; it puts `CreateEntity` initializers into the target entity's attribute declaration order (the one ordering change relative to the resolved model's ascending-key listing); it keeps the two principal modes and their allow branches explicit with the actor-free families unrepresentable outside them; it carries a `TenantIsolation` guarantee's resolved access relation and endpoint identities over unchanged, with the stored types of its actor-free tenant/protected terms recording the (unverified) obligation's parameters; it binds escalation-case scope terms to their authority's scope endpoint; and it carries the distinguished-`User` identity — selected once by the resolver, validated and carried by the typechecker's signature — into the normalized model as an independent anchor (`modelUserEntity`, propagated rather than re-derived from a name, a position, or a term) for the backends' subject and `Actor` checks. Normalization is deterministic structural canonicalization of one authored document and nothing else — no boolean simplification, constant folding, operand reordering, policy evaluation, proof checking, or semantic optimization, and no claim of alpha-equivalence or canonical equality between differently authored documents (white-box tests pin foldable authored shapes surviving verbatim). An ordinary well-typed document normalizes with no user-error class; the only refusal is the internal normalizer-invariant class (exit status 2) for post-`Typed` inconsistencies — the normalizer first re-runs the complete checking pass as a consistency gate and reclassifies anything it reports, and every structural impossibility it meets while building (arity mismatches, non-bijective initializers, incomplete rankings, scope mismatches) is the same internal class — unconstructible through any public invocation and pinned by white-box tests over the pure seam. The stage adds no dependency; external code cannot construct or forge a normalized document, coerce `Typed` to `Normalized`, import the normalized representation or the pass module, or recover the internal model (all pinned by compile-fail probes). `Normalized` attests deterministic structural normalization of a well-typed document only: the typed normalized Core the contract renderer, Agda backend, and target emitters must share now exists — its implemented consumers are the contract renderer below, the single-obligation verifier slice of `mithril verify`, and the confined Wasp Confinement Profile v0/v1 adapter of that same obligation (`mithril wasp generate|check`) — but producing it evaluates no policy, establishes no guarantee, generates nothing, and verifies nothing; only the separate verifier boundary, for exactly one supported obligation of a supported document, generates a checked Agda artifact, and nothing beyond that one obligation is verified.
- **The first verification boundary is implemented, and it is deliberately narrow.** `Mithril.Core.Verification.verifyCoreDocument` accepts exactly a `CoreDocument Normalized` (pinned by a downstream compile-fail probe) and decides, first and purely, whether the document lies inside the one implemented support rule: exactly one selected guarantee, a `NoSelfPrivilegeEscalation` guarantee whose shared authority evidence — binary authority relation with a `User` subject endpoint whose entity must be exactly the normalized model's independently carried distinguished-`User` identity (a mismatch, however coherently the subject endpoint, parameter types, and `Actor` terms were redirected together, is a verifier-invariant violation: never UNSUPPORTED, never VERIFIED, no checker launched, no Wasp lowering), a distinct-entity scope endpoint, two-value declared-order payload enum with absence as bottom — is validated once, and whose non-empty case collection consists entirely of cases each matching exactly one of two exact structural rules, classified independently in authored order and tagged in the shared plan (`Mithril.Core.Internal.NspeSupportPlan`: shared facts plus a `NonEmpty` of rule-tagged case plans; never only the first case, never a case dropped, reordered, or deduplicated). Rule 1 (change-other) is the mechanized safe `Membership.changeRole` proof rule of the Agda spike: an `AuthenticatedOnly` case action with exactly the subject/scope/payload parameter list, a `SetRelation` effect binding subject↦subject parameter, scope↦scope parameter, payload↦payload parameter, a case scope of exactly the scope parameter, and an allow policy of exactly `And(LessOrEqual(Some(top value), Lookup(authority, [Actor, scope])), And(Not(Equal(Actor, subject)), IsSome(Lookup(authority, [subject, scope]))))`. Rule 2 (bounded self-update): an `AuthenticatedOnly` case action with exactly the scope/payload parameter list, a `SetRelation` effect binding subject↦`Actor`, scope↦scope parameter, payload↦payload parameter, a case scope of exactly the scope parameter, and an allow policy of exactly `LessOrEqual(Some(payload), Lookup(authority, [Actor, scope]))` with no further conjunct (no explicit `IsSome`: it is redundant under absence as bottom and is deliberately not accepted). The rules are disjoint by declared arity, so no case matches both; a case matching neither makes the whole obligation UNSUPPORTED with reasons anchored at the offending case, action, parameter, policy, effect, or case-scope site. The gate inspects stored identities and evidence only: no JSON byte comparison, no filename recognition, no model hashing, no reparsing or re-resolution or re-inference, no policy evaluation, and semantically equivalent but differently authored shapes are deliberately UNSUPPORTED. For a supported document the verifier deterministically generates one Agda obligation module from the normalized evidence (fixed module name and theorem names; document names appear only escaped inside line comments) with one complete proof group and checked manifest per case — rule 1: case-scope-is-scope-argument, policy-actor-distinct, actor-authority-unchanged, no-self-escalation; rule 2: case-scope-is-scope-argument, policy-bounds-payload, actor-authority-written, no-self-escalation — each case in an inner module qualified by its zero-based authored position, while a singleton rule-1 document renders the original flat module byte-for-byte (the golden `test/fixtures/nspe.generated.agda`; the two-case golden is `test/fixtures/nspe-self-update.generated.agda`); verifies the plan-derived required theorem inventory (every theorem of every case), materializes it with the compile-time-embedded trusted kernel modules into a fresh isolated temporary workspace (never the repository, working directory, or any environment-selected location; cleaned on every path), and invokes exactly Agda 2.8.0 with `--safe --no-libraries --ignore-interfaces` across a process boundary — the host imports no Agda compiler internals, and no kernel change, postulate, or unsafe feature was needed. Results: VERIFIED (exit 0) only when every selected case of the one selected obligation is supported and every required theorem of every case was accepted — the singleton rule-1 report is byte-for-byte unchanged, every other report lists each case with its position, rule, action, and theorems; UNSUPPORTED (exit 3) with non-empty deterministic sorted deduplicated reasons, decided before any checker runs — a document selecting no guarantees is unsupported, never vacuously verified, and the unsafe guard-free variant and the dangerous floor-lowering mutation (`test/fixtures/acme-nspe-dangerous.mir.json`, a genuine self-promotion counterexample) are unsupported, not proved violations; every checker problem (missing or unlaunchable Agda, wrong version, workspace failure, nonzero exit after gate acceptance, signal termination, missing generated theorem, forged-model inconsistency) is a tool/internal failure with exit 2 — never `VIOLATED`, which this milestone can never emit and which has no representation in the vocabulary. The support gate, generator, and orchestration live in the private `core-internal` sublibrary (`Mithril.Core.Internal.Verify`); the embedded kernel bytes (`Mithril.Core.Internal.AgdaKernel`) and the production process runner (`Mithril.Core.Internal.AgdaChecker`) are hidden modules of the public library; `mithril verify FILE` (`Mithril.Command.Verify`) reuses the complete validate pipeline for input failures byte-identically. The production checker boundary added the GHC boot libraries `directory`, `filepath`, and `process` as direct dependencies of the public library; no other dependency was added. The Haskell frontend and generator, the embedded kernel modules, the external Agda 2.8.0 toolchain, and the support rules themselves are trusted components; verification of one supported document establishes exactly the selected cases of its one selected obligation and nothing else — no other action, unselected authority writer, family, document, or semantic-preservation property.
- **The first target adapter consuming normalized Core is implemented, and it is exactly two confined profiles.** `Mithril.Core.Wasp.renderWaspBundle` accepts exactly a `CoreDocument Normalized` (pinned by downstream compile-fail probes for `Parsed`, `StructurallyValid`, `Resolved`, and `Typed`) and consumes the one shared NoSelfPrivilegeEscalation support plan — `Mithril.Core.Internal.NspeSupportPlan`, the single package-private statement of the supported-shape classification, its canonical identity preflight, its per-case rule tags, and the resolved metadata (identities, `Sourced` names, endpoint and case-scope bindings, declared enum members, the materialized ranking) — that `Mithril.Core.Internal.Verify` also consumes for the Agda generator; neither backend restates any part of the classification, a document the verifier reports unsupported is unsupported to the emitter with the identical reasons, and malformed normalized evidence fails closed as the same verifier-invariant class before anything is generated or any checker runs. Two profiles exist, selected by the profile dispatcher over the ordered rule tags of the shared plan's case collection (never re-deriving a rule, never inspecting the normalized model, never inferring the profile from an operation count): exactly `[rule 1]` selects Wasp Profile v0, exactly `[rule 1, rule 2]` — the change-other case at position 0 and the bounded-self-update case at position 1, in authored order — selects Wasp Profile v1, and every other sequence (a singleton rule-2 case, two rule-1 cases, the reversed pair, two rule-2 cases, three or more cases) is refused as unsupported (exit 3) with deterministic reasons anchored at the offending case (`… case 1 matches rule 1 (change-other), but Profile v1 requires rule 2 (bounded-self-update) at position 1`) or at the guarantee (`… this guarantee selects 3 cases`), each prefixed by the capability sentence `Wasp Profile v0 lowers exactly one Rule-1 case and Wasp Profile v1 exactly the ordered Rule-1, Rule-2 case pair`, before any lowering — and therefore, in the CLI, after verification but before any destination is resolved, inspected, staged, backed up, or written; arbitrary multi-case lowering is not implemented, and VERIFIED-but-Wasp-UNSUPPORTED remains a valid outcome. The selected profile is an explicit identity carried by the bundle, its summary, its ownership marker, its manifest, and the CLI report. The emitter has no lowering rule of its own: every Prisma model, enum, value, and field name, every TypeScript identifier, each Wasp operation, its route, and every managed path is a fixed target name derived from the role a declaration plays in the supported shape (`MithrilSubject`, `MithrilScope`, `MithrilAuthority`, `MithrilPayload`, the rule-1 Action `mithrilCaseAction` at `/operations/mithril-case-action`, the rule-2 Action `mithrilSelfUpdateAction` at `/operations/mithril-self-update-action` — Profile v1 only, exported by the same generated file — the fields `subjectId`/`scopeId`/`payload`, the arguments `subject`/`scope`/`payload` for rule 1 and `scope`/`payload` for rule 2) or, for enum values, from the canonical declaration position of the value's identity (`Value0`, `Value1`) — never an authored name, so nothing authored can collide with a Prisma scalar type, a Wasp auth model, a TypeScript keyword, or another target name, the inventory is the same for every supported document, and authored names survive only as escaped comment and string metadata and in the manifest's explicit authored-to-target mapping (the committed rename variants under `test/fixtures/wasp-renames` — a scope entity named `String`, Wasp's auth model names, reserved words, acronyms and digits, boundary leading characters, authored names spelled like the target names, and a declaration order differing from the ranking — are rendered by the test suite and installed and built by the Wasp job). The ranking facts (the materialized ranking, its bottom and top with validated numeric ranks, the absent rank) come from the shared plan, the only ranking authority; the emitter scans, classifies, and defaults nothing. The pure renderer establishes supported-shape lowering only and no rendered byte claims verification; VERIFIED provenance is stated only by the CLI generation path, which requires the production verifier to report VERIFIED before rendering. The bundle is a Wasp Confinement Profile: a normal Wasp 0.25.0 application on PostgreSQL — `main.wasp.ts` (username-and-password auth, one route and page, the profile's authenticated Actions: one for v0, two for v1), `schema.prisma`, the generated operation file `src/mithrilCaseAction.ts` (every Action: Wasp authentication required, `context.user.id` as the only identity, argument validation with 400, the authorization reads and the `SetRelation` update in one Prisma interactive transaction at `Serializable` isolation, one uniform 403 for every denial, a fixed three-attempt `P2034` retry ending in 409, a stable 500 otherwise, no raw SQL, and the materialized enum ranking as the only role ranking; the rule-2 Action of Profile v1 locates the actor's own tuple at `(actor, scope)`, takes the plan's absent rank when it is missing, authorizes exactly when `payloadRank <= actorRank` — no separate membership condition — and updates exactly that tuple, with no caller-supplied subject argument), `package.json` (Wasp's required dependencies; the Prisma runtime Wasp supplies, no second ORM or driver), `tsconfig*.json`, `vite.config.ts`, `.wasproot`, `.gitignore`, `.npmrc`, the profile's fixed-bytes ownership marker `.mithril-wasp-profile` (two distinct literal markers, one per profile), a static `src/MainPage.tsx`, and `mithril.manifest.json` (format version `0` for Profile v0, byte-identical to before; format version `1` for Profile v1, with the complete ordered `operations` array mapping each case to its operation, route, file, and provenance) — the same fourteen managed files for both profiles, deterministic in the document's content alone, with paths that depend on nothing. `mithril wasp generate CORE_FILE WASP_ROOT` (`Mithril.Command.Wasp`, over `Mithril.Core.Internal.WaspFilesystem`) runs the validate pipeline, requires the production verifier to report VERIFIED, renders the complete bundle before touching the filesystem, accepts the root path lexically only (an empty, `.`, `..`, or trailing-separator component is refused, never normalized;
