# Guidelines for coding agents working on Mithril

This file is operational guidance for AI coding agents (and useful context for humans supervising them). It is repository-specific; follow it over generic defaults.

## What this project is

Mithril is experimental formal-verification infrastructure for authorization and data-access security in AI-generated web backends. Intended flow: natural-language intent → authored Mithril Core JSON (written by a human, optionally proposed by an untrusted LLM) → one deterministic Haskell frontend → typed normalized Core → human-readable contract, Agda checking, and deterministic Wasp generation. `docs/compiler-architecture.md` is authoritative for this pipeline and for artifact ownership.

**Current status: the four frontend boundaries plus the deterministic contract renderer — and nothing beyond them — are implemented.** The repository contains documentation (including the accepted compiler-architecture specification, `docs/compiler-architecture.md`), repository configuration, an experimental Agda semantic spike under `agda/` (see `agda/README.md`) — an exploratory mechanization of candidate kernel semantics that neither selects Agda as the implementation language nor constitutes a product prototype — the Core v0 concrete-syntax checkpoint described below, and the Haskell host tool with pinned Haskell CI: Cabal package `mithril-ir`, whose `mithril` CLI prints help and version output and implements `mithril validate FILE` — deterministic JSON parsing, structural Core v0 validation of a document against the canonical `core/schema.json` compiled into the tool at build time, complete Core v0 name resolution, whose success is carried as an explicit internal decoded and name-resolved Core representation (identifier-based references with JSON source paths; generic JSON ends at the internal decode boundary), complete Core v0 static typing over exactly that representation, and deterministic Core v0 normalization of the well-typed document into a distinct explicit internal typed normalized representation (statically typed terms, materialized enum ranks, explicit endpoint bindings, declaration-ordered `CreateEntity` initializers, explicit guarantee structure) — and `mithril contract FILE`, the same complete pipeline followed by deterministic rendering of the normalized document as a line-oriented, human-readable security contract (the first consumer of the typed normalized Core; byte-frozen golden outputs) — with unit tests, process-level CLI tests, and downstream plus in-package API-boundary compile-fail probes over these boundaries. There is still no verifier or generator: validation, resolution, typing, and normalization establish JSON shape conformance, name resolution, static well-typedness, and deterministic structural normalization only; normalization preserves authored policy and operand structure and performs no simplification, folding, or evaluation — `CreateEntity` initializers alone are placed in target-attribute declaration order — and claims no canonical equality between differently authored documents; contract rendering deterministically restates the normalized document for human review and nothing more — it evaluates no policy and is not a semantic diff; no policy is evaluated, no guarantee is established, and nothing is proved.

## Core v0 concrete syntax

- `core/schema.json` (JSON Schema, draft 2020-12) is the source of truth for the current external JSON shape of a Mithril Core v0 document.
- `examples/acme/acme.mir.json` is a handwritten source example. Neither file is generated; both are edited by hand.
- Schema acceptance is structural validation only — required fields, closed constructor sets, principal-mode surface shape, classification/effect/result compatibility. It is not semantic validation and not proof: declaration uniqueness, name resolution, static typing, enum-order permutation validity, and normalization are now established by the host tool's implemented resolver, typechecker, and normalizer stages, while policy evaluation and guarantee verification still require the later verifier, which does not exist.
- Haskell is the selected implementation language for the deterministic host tool (see `docs/compiler-architecture.md`). The host tool now implements the four frontend boundaries — `mithril validate FILE`: JSON parsing, structural validation against this schema, complete Core v0 name resolution, complete Core v0 static typing, and deterministic Core v0 normalization — plus the deterministic contract renderer over their result (`mithril contract FILE`), and nothing after those: no verifier or emitter exists. `Typed` is an opaque stage attestation about names and static types; `Normalized` is the opaque attestation that the well-typed document was additionally normalized into the explicit typed normalized Core representation — structural canonicalization of one authored document, not evaluation, not verification — and the rendered contract is a deterministic restatement of that representation for human review, not evaluation, not a semantic diff, and not proof.
- The Agda spike under `agda/` remains a separate exploration; it does not consume this JSON. It now contains one hand-transcribed application slice — a checked NoSelfPrivilegeEscalation case for `Membership.changeRole` (see `agda/README.md`) — which does not establish the JSON document's guarantees.

## Hard rules

1. **No Git or GitHub operations.** Do not commit, branch, merge, rebase, push, tag, or open/modify pull requests, issues, or releases. The human operates version control.
2. **No unrequested scope expansion.** Do exactly what was asked. Do not add source directories, package manifests, CI workflows, architecture documents, templates, or "helpful" extras that were not requested.
3. **No arbitrary escape hatches inside verified policy logic.** Once implementation exists, verified policy logic must never embed arbitrary JavaScript, raw SQL, FFI calls, or other unanalyzable code. Anything the verifier cannot reason about does not belong inside the verified boundary.
4. **No unchecked proof escape hatches for claimed guarantees.** Never use `postulate`, `unsafe`, `assume`, `admit`, `sorry`, or equivalent mechanisms to make a claimed guarantee check. An axiom needed for a documented, reviewed trusted-computing-base assumption is a human decision, not something an agent introduces to make a build pass.
5. **Never hand-edit generated files.** Once code generation exists, generated artifacts are modified only by changing their source and regenerating. If a generated file looks wrong, fix the generator or the input, and say so.
6. **Do not overstate security.** Documentation and code you write must describe TenantIsolation, AuthenticatedMutation, and NoSelfPrivilegeEscalation (and any future properties) as targets until they are actually verified, and must never claim general security.

## Decided architecture — follow it

The following decisions are made and documented. Do not re-open them, contradict them, or describe them as undecided.

- **Haskell is the selected implementation language** for the deterministic host tool: the CLI, the frontend stages (conceptually `Raw -> Resolved -> Typed -> Normalized`), the contract renderer, and the backend emitters. Agda remains the separate formal backend/checker, reached through generated files and a process boundary — the Haskell decision does not make Haskell the proof backend, and the host tool must not import or depend on Agda compiler internals as a Haskell library.
- **The Haskell toolchain configuration is fixed.** GHC 9.12.4, cabal-install 3.18.1.0, and the GHC2021 language edition are the supported configuration. The canonical commands, run from the repository root, are `cabal check`, `cabal build all --enable-tests`, `cabal test all --test-show-details=direct`, `sh test/api-probes/run-api-probes.sh` (the API-boundary compile-fail probes — the downstream package attacks plus the in-package identifier non-coercion attacks; requires a POSIX shell), `cabal run mithril -- --help`, `cabal run mithril -- --version`, `cabal run mithril -- validate examples/acme/acme.mir.json`, and `cabal run mithril -- contract examples/acme/acme.mir.json`. Do not add dependencies and do not select packaging or distribution mechanisms without an explicit task.
- **The name-resolution boundary is implemented.** After structural validation, `Mithril.Core.Resolution.resolveCoreDocument` enforces declaration-name uniqueness independently per namespace (entities, enums, relations, and actions globally; attributes, endpoints, and parameters per owner) and resolves every Core v0 name reference in its correct namespace, including the narrow declared-type lookup that selects the entity-local attribute namespace of an `Attribute` projection — the only typing-shaped judgment in the stage. `Resolved` attests names only — static typing is the next implemented boundary (below), and policy evaluation and guarantee verification remain unimplemented — so a resolved document can still fail the typechecker. Deterministic maps and sets come from the direct `containers` dependency (`>= 0.7 && < 0.8`, resolves 0.7, BSD-3-Clause, a GHC boot library, part of the trusted computing base). User name errors exit 1; internal resolver-invariant failures (schema/resolver drift after successful structural validation) are classified separately and exit 2 — with the schema compiled in, no public invocation can construct these internal states, so their classification and rendering are pinned by unit tests over the pure seam. `Resolved` now carries the explicit internal decoded and name-resolved Core representation: the frontend decodes the structurally valid JSON — in one interpretation shared between its internal schema decoder and the resolver — into explicit Haskell nodes whose resolved references are namespace-specific internal identifiers (owner-local identifiers embed their owner) with declaration names kept only as diagnostic metadata, and every node and reference retains its originating JSON path. The raw JSON value is discarded at that internal decode boundary; the representation is hidden inside the package — it lives in a package-private sublibrary (an internal testability and encapsulation mechanism, not a packaging decision): the production public library depends on it and consumes the representation from it, the package's own white-box test suite and in-package probes may also depend on it, and no external package can depend on it or import its modules — so external code cannot construct its nodes, mint or coerce identifiers, or extract JSON from a resolved document, and the identifier namespaces are distinct data types that even in-package code cannot coerce into one another. The implemented typechecker and normalizer consume exactly this representation — never generic Aeson `Value` — the implemented contract renderer consumes exactly the normalizer's output the same way, and the Agda emitter and backend adapters must do likewise, without independently reinterpreting raw JSON or rebuilding name resolution. The representation is not typed normalized Core: whether it is well-typed is attested only by the separate `Typed` stage index, normalization constructs a distinct normalized model from it, and it remains unverified and proves no property.
- **The static-typing boundary is implemented.** After name resolution, `Mithril.Core.Typing.typecheckCoreDocument` checks every Core v0 static-typing judgment over the explicit resolved representation — and only over it: no raw JSON is reread and no name resolution is rebuilt. The type language is the four value types (`Bool`, `Unit`, `Enum E`, `EntityRef E`) plus one-level optional types over them for relation-payload presence. The judgments: term, policy, effect, and result typing; operand compatibility (`And`/`Or`/`Not` and every allow policy at `Bool`; `IsSome` over an optional type; `Equal` over two operands of one type, with equality total at every type; `LessOrEqual` over two operands of one ordered type — an enum with a declared order, directly or under the optional level with absence as bottom, mirroring the Agda spike's candidate semantics); enum-order complete-permutation validity; relation endpoint arity and per-position endpoint entity types at `Lookup`, `SetRelation`, and `RemoveRelation` sites plus `SetRelation` payload typing; entity-reference `Observe` and `DeleteEntity` targets; `CreateEntity` initializer completeness and value typing; and guarantee well-typedness — `TenantIsolation` guarantees whose structural `access` relation is binary with two distinct designated endpoints (which therefore cover it) and a subject endpoint of entity type `User`, and whose actor-free case terms are typed in their action's environment (a `tenant` of exactly the tenant endpoint's entity-reference type, a `Bool` `protected`; presence of a `(subject, tenant)` tuple in the access relation is the baseline tenant access of the still-unverified obligation — role floors stay in action allow policies, and the former arbitrary per-case `tenantAccess` policy no longer exists), and `NoSelfPrivilegeEscalation` authorities whose subject endpoint references the distinguished `User` entity, whose subject and scope endpoints are distinct and cover the relation's endpoints, whose relation payload is exactly the declared-order `payloadOrder` enum, and whose case scope terms correspond one-to-one, at the scope endpoint's entity type, with the authority's scope endpoints. Typing diagnostics are deterministic — authored JSON-pointer locations from the representation's retained source paths, aggregated across independent sites, sorted, deduplicated, dependent cascades suppressed — and exit 1; shapes of the resolved model the typechecker cannot interpret are impossible after successful resolution, are classified as internal typechecker-invariant errors with exit 2 (unconstructible through any public invocation; classification and rendering pinned by white-box tests over the pure seam), and dominate. The stage adds no dependency and no second representation: `StagePayload Typed` is the same explicit resolved model, the `Typed` index is the attestation, and external code can neither construct a typed document, nor coerce `Resolved` to `Typed`, nor import the internal typechecker module (all pinned by compile-fail probes). `Typed` attests static well-typedness only: it is not normalization, not policy evaluation, not guarantee truth, and not verification — a well-typed document's guarantees remain unverified proof obligations.
- **The normalization boundary is implemented.** After static typing, `Mithril.Core.Normalization.normalizeCoreDocument` accepts exactly a `CoreDocument Typed` — the stage indexes make anything earlier unacceptable — and constructs the explicit typed normalized Core representation: a distinct package-private model (`Mithril.Core.Internal.Normalized`, in the same private sublibrary as the resolved representation, alongside the shared static type language `Mithril.Core.Internal.StaticType`), never the resolved model under another stage tag. Normalization stamps every term with the static type the typechecker determined — the normalizer reuses the typechecker's shared internal elaboration/type-query facility (`inferValue`/`inferPolicy` over the model `Signature`, plus its ordered-comparison classification, built like the declared-type projections on the shared static-type module) and restates no typing, projection, or classification rule, so each of those judgments has exactly one statement and later backends never rerun type inference; it preserves every resolved namespace-specific identifier while keeping declaration names and source paths as diagnostic/rendering metadata that never determines semantic linkage; it materializes declared enum orders into explicit complete rankings and records each `LessOrEqual`'s ordered reading (which enum ranks it, and whether at the absence-as-bottom optional level); it pairs lookup and relation-effect endpoint terms one-to-one with the declared endpoints they bind; it puts `CreateEntity` initializers into the target entity's attribute declaration order (the one ordering change relative to the resolved model's ascending-key listing); it keeps the two principal modes and their allow branches explicit with the actor-free families unrepresentable outside them; it carries a `TenantIsolation` guarantee's resolved access relation and endpoint identities over unchanged, with the stored types of its actor-free tenant/protected terms recording the (unverified) obligation's parameters; and it binds escalation-case scope terms to their authority's scope endpoint. Normalization is deterministic structural canonicalization of one authored document and nothing else — no boolean simplification, constant folding, operand reordering, policy evaluation, proof checking, or semantic optimization, and no claim of alpha-equivalence or canonical equality between differently authored documents (white-box tests pin foldable authored shapes surviving verbatim). An ordinary well-typed document normalizes with no user-error class; the only refusal is the internal normalizer-invariant class (exit status 2) for post-`Typed` inconsistencies — the normalizer first re-runs the complete checking pass as a consistency gate and reclassifies anything it reports, and every structural impossibility it meets while building (arity mismatches, non-bijective initializers, incomplete rankings, scope mismatches) is the same internal class — unconstructible through any public invocation and pinned by white-box tests over the pure seam. The stage adds no dependency; external code cannot construct or forge a normalized document, coerce `Typed` to `Normalized`, import the normalized representation or the pass module, or recover the internal model (all pinned by compile-fail probes). `Normalized` attests deterministic structural normalization of a well-typed document only: the typed normalized Core the contract renderer, Agda backend, and target emitters must share now exists — its first implemented consumer is the contract renderer below — but no policy is evaluated, no guarantee is established, nothing is generated, and nothing is verified.
- **The contract-rendering boundary is implemented.** `Mithril.Core.Contract.renderCoreContract` accepts exactly a `CoreDocument Normalized` — the stage indexes make anything earlier unacceptable, pinned by a downstream compile-fail probe — and deterministically renders the explicit typed normalized representation as the line-oriented, human-readable security contract: fixed `Mithril Core v0` header and model name, then entities, enums with materialized ranks, relations, actions (parameters, principal mode, classification, allow policies, effect, result), the selected guarantees explicitly labelled unverified proof obligations (every TenantIsolation access relation and endpoint plus every case term; every NoSelfPrivilegeEscalation authority component and case scope), and a fixed limitations section, in normalized declaration order, with terms in a fully parenthesized constructor-preserving syntax carrying their stored static types and every reference rendered through its resolved identifier and declaration metadata. The renderer repeats no earlier stage — no JSON rereading, no name resolution, no type inference, no endpoint or scope rebinding, no rank re-derivation — and performs no evaluation or simplification; output contains no internal numeric identifiers, timestamps, file paths, or JSON details, ends with exactly one final newline, and depends only on the document's content, never its filesystem path — the exact bytes are frozen by golden and literal tests. `mithril contract FILE` reuses the complete validate pipeline for input failures (byte-identical diagnostics, same exit classification) and writes only the contract to stdout on success. An ordinary normalized document renders with no user-error class; the only refusal is the internal contract-renderer invariant class (exit status 2) for forged-model referential inconsistencies that are impossible through the public pipeline (pinned by white-box tests over the pure seam). The contract is a review artifact only: it establishes nothing, verifies nothing, and is not a semantic diff, a policy evaluator, or proof.
- **The structural-validation boundary is decided, and its validator is provisional.** Aeson performs JSON parsing. Known, deliberate gaps — not desired contracts: duplicate JSON object members are not rejected (Aeson member semantics; which occurrence wins is not part of any Mithril contract and must not be relied on), and no input or resource limits are enforced; both remain unresolved. Structural validation is performed by the native Haskell package `jsonschema`, pinned exactly to 0.3.0.1 (MPL-2.0; a runtime dependency and part of the trusted computing base for structural claims) and trusted only for the explicitly gated Core v0 schema profile: loading fails closed on the exact draft 2020-12 `$schema` URI, a closed schema-keyword inventory, local unescaped `#` references only, annotation-only `$ref` siblings, and per-`pattern` regex compilation — a direct `regex-tdfa` dependency (the backend's own engine, also in the trusted computing base) compiles every `pattern` while the gate runs, so an uncompilable pattern fails loading instead of throwing during validation. The canonical `core/schema.json` — still the single authoritative source for the external Core v0 JSON grammar — is compiled into the library at build time (embedded via Template Haskell with the file registered as a build dependency) and is the only schema the public validation API can use: the library exposes a bytes-level profile check for tests and tooling, but only the compiled-in schema value can mint a `StructurallyValid` stage. No runtime file lookup or environment override — in particular `mithril_ir_datadir`, which once selected the package data directory — can substitute the grammar; regression tests pin a hostile override as having no effect. This is provenance by construction, not a cryptographic-integrity or formal-verification claim. Changing the schema's keyword usage, the profile gate, or the pin requires explicit backend-compatibility review plus updating the tests that pin the keyword inventory. This is not a claim that Mithril implements arbitrary Draft 2020-12 schemas.
- **Audit schema and frontend evolution together.** For every `core/schema.json` change covered by the [architectural schema-and-resolver rule](docs/compiler-architecture.md#schema-and-resolver-evolution), audit the internal schema decoder and the decoded/resolved representation's construct coverage as well as `Mithril.Core.Resolution`, the static typechecker (`Mithril.Core.Internal.Typecheck`, exposed through `Mithril.Core.Typing`), and the normalizer with the normalized representation's construct coverage (`Mithril.Core.Internal.Normalize` and `Mithril.Core.Internal.Normalized`, exposed through `Mithril.Core.Normalization`), enumerate changed constructors and reference locations, and add relevant targeted regressions in the same change. A successful rebuild or structural-validation run is insufficient: `addDependentFile` notices changed bytes, not decoder, representation, resolver, typechecker, or normalizer completeness. Completeness remains a manually reviewed obligation, not an automated proof. Do not create a second schema copy or describe this audit as automated.
- **Python is not part of the product or CI.** A Python `jsonschema` oracle may serve as transient development evidence outside the repository; never add Python files, Python CI steps, or a documented Python runtime dependency.
- **`docs/compiler-architecture.md` is authoritative** for the compiler pipeline and for artifact ownership (authored vs. derived vs. trusted). `core/schema.json` remains authoritative for the external Core v0 JSON shape.
- **One frontend, one typed normalized Core.** Contract generation, Agda generation, and executable enforcement must all consume the same typed normalized Core produced by the single frontend. Never create or imply an independent per-backend interpretation of the JSON.
- **No LLM output in the deterministic path.** An LLM may at most propose the authored Mithril JSON. LLM-generated Agda, contracts, normalization, or target enforcement code is forbidden.
- **Generated files are never hand-edited** (hard rule 5) — and, today, nothing is generated: the `Mithril.Acme` proof slice remains hand-transcribed authored Agda, not a derived artifact of `examples/acme/acme.mir.json`.

## Still undecided — do not decide them

- **Do not invent lint or formatting commands.** The Haskell build and test commands listed above are now real, but no lint or formatting command exists or has been selected; if a task seems to require one, report that it does not exist instead of fabricating one. The experimental Agda spike is unchanged: its only real commands are the authoritative checks documented in `agda/README.md` — run exactly those, and only when a task involves the spike.
- **Haskell choices beyond the current dependency set are open.** Packaging and distribution mechanisms have not been decided, and the provisional `jsonschema 0.3.0.1` validator is a checkpoint choice, not a settled endorsement — whether it stays, is replaced, or is reimplemented remains open; do not entrench or reopen it without an explicit task.
- **Emitter surface details are open.** Exact generated filenames, the generated-artifact metadata/manifest format, and the final target-adapter API are deferred to emitter design; do not freeze them in documentation or code.

## Reporting

At the end of every task, report:

- **Files changed** — created, modified, or deleted, by path.
- **Decisions made** — anything you chose that the task did not fully specify.
- **Checks run** — what you actually verified and how (and what you could not verify).
- **Unresolved questions** — anything ambiguous, blocked, or deferred to a human.

Report failures and skipped steps plainly. A wrong "done" is worse than an honest "blocked".
